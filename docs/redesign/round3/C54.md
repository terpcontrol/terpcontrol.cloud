# C54 — "Der Befund"

**Family:** hybrid (C14 × C36 × C11-slider) · **Centre of gravity:** a finding is a thing you can walk
into, and it carries its own proof and its own remedy.

---

## 1. Thesis

**The primary object is a *Befund*: a named finding with a time span, a body of evidence, and named German
relations — and a Befund is a Ding like every other Ding, so you walk from the finding to its proof, and
from any thing back to the findings that cite it.**

C14 got the question right (*was ist anders?*) but its findings were rows in a list — dead ends with one
tap target each. C36 got the structure right (everything is a walkable Ding with one screen shape) but had
nothing to say about what matters right now; its home screen is an inventory in reverse-chronological
order. Fuse them and the finding becomes an object with edges:

```
Befund „Nachts war es wärmer als das Ziel"
  ├ Belege  → das Bildpaar · das Messfenster · die Ereignisse · die Heizung (Dose 1)
  │           · das Ziel, das damals galt
  ├ Abhilfe → Nachtziel ändern · Heizung prüfen · Zettel anlegen   (each a walk, never prose)
  ├ Betrifft→ A1 A2 A3 · Gerät „Controller Keller"
  └ Verlauf → seit wann · wer quittiert hat · was daraufhin geändert wurde
```

The walk runs both ways: the socket's own Tafel has a `Befunde` section saying *which findings name me*;
the `ziel` Ding's history says *this value was raised because of Befund X, by Anna, on 12.09.*

C14's discipline survives verbatim: **the product describes, it never diagnoses.** What it now adds — the
thing sixty concepts scored 4.93/10 on — is **Abhilfe**: a short, deterministic, precondition-gated list of
*Dinge you can walk to and change*, generated from data the app already holds. Never a sentence of advice.
Always a link.

## 2. What comes from where

| Source | What this concept takes |
| --- | --- |
| **C14** | the question (*was ist anders seit ich zuletzt geschaut habe*) · the picture pair as the comparison instrument · the printed deterministic ranking `|Δ| / max(σ₁₄, σ_floor)` · the two-register row (prose + tabular-nums in one DOM node) · the frame-metrics pipeline and the cull · the refusal to diagnose · the double-feed guard whose warning carries a *picture* |
| **C36** | one screen shape (Kopf · Körper · Handlungen · relations · Verlauf · Werte) · one gesture (tap a Zeile, it becomes the Subjekt) · German relation names as the only taxonomy · reveal by capability and by data · the `Werte` row showing raw JSON and the literal GET · corrections instead of edits · six stored arts, the rest projected read-time |
| **C11's slider** | one cursor, several projections, drag any and all move · a pinned scrub header instead of a tooltip · **pause as the disclosure gesture** — stop and the instant under the cursor unfolds into measured-vs-target-vs-delta, which sockets ran, which diary entries fell within ±2 h, and the frame's own exposure/sharpness verdict; nothing persisted, self-cancelling, hiding no feature class |

## 3. Information architecture

Three routes. No tab bar (C36's discipline; the cost is named in §14).

| Route | Guard | What |
| --- | --- | --- |
| `/list` | AuthGuard | Zelte. Exactly one → straight through, as today. |
| `/z/:tent_id/:ding_id?` | AuthGuard (+ share bypass) | **The browser.** One component. `ding_id` absent ⇒ the Zelt is the Subjekt and the Kopfbefund is open. |
| `/z/:tent_id/verlauf?…` | AuthGuard (+ share) | The chart. The only non-Tafel screen, always entered with a measure and a window already applied. |

Kept, so persisted user data resolves:

```
/device/:id/charts?<q>   → 301 /z/<tent_of(id)>/verlauf?<q>   (applyViewParams back-compat branch intact)
/device/:id/diary        → 301 /z/<tent_of(id)>              (mergeDiaryQueryParams honoured)
/device/:id/settings     → 301 /z/<tent>/ziele  for controller/fridge
                         → kept verbatim for fan/light/plug/dryer (§11)
/login /account /shares /demo /classes /diagnostics /device/:id/testmode   untouched
```

`ShareLink.page` stays `'charts' | 'diary'`. No enum change, no migration.

**Das Zelt über dem Gerät.** `Tent { tent_id, owner_id, name, device_ids: string[], timezone, created_at }`.
Migration creates **one Tent per claimed device**, named after the device — so nothing changes for anyone
until they act. `+ Gerät in dieses Zelt` appears on the Zelt Tafel **only when the account holds ≥ 2
devices** (reveal by data). Everything cross-device then merges: one diary, one day counter, one Befund
list, one film, one `Zettel` board. Each Befund carries `belege.geraet`, so a merged tent still says which
box measured what: `gemessen von „Controller Keller"`.

### Collections (all cloud-side Mongo; `device.configuration` untouched, no new firmware keys)

```ts

  befund_id, tent_id,
  regel: BefundRegel,          // closed set of 16, §6
  befund_key,                  // sha1(regel + subjekt + fensterbucket) — dedupe, so a persisting
                               // finding says "seit 3 Tagen" instead of reappearing daily
  t, t_end: number|null,       // the evidence window. null = still open.
  titel_key, titel_daten, wert_key, wert_daten,   // i18n key + numbers. NEVER a stored German string.
  schwere: 0|1|2,              // 0 ruhig · 1 auffällig · 2 Hardware/Sicherheit

  belege: { bildpaar?: [image_id, image_id], reihe?: {measure, von, bis}, ereignisse?: ding_id[],
            geraet?, dose?, ziel?, regime_schritt? },
  abhilfen: Abhilfe[],
  betrifft: { pflanzen: [], dosen: [], geraete: [] },
  quittiert_von?, quittiert_am?,
  still_bis?,                  // instance-scoped snooze with a printed expiry — §5 audit
  regelsatz_version, berechnet_am }

Abhilfe { art: 'ziel_aendern'|'dose_pruefen'|'zettel'|'gabe'|'kamera'|'grenze',
          ding_id?,            // what you walk to
          vorschlag?,          // prefilled value, always editable
          i18n_key, daten }

ZielVersion {                  // THE FIX for "every chart draws today's target over last month's data"
  ziel_id, tent_id, device_id,

  gesetzt_von?,                // mensch ding_id
  wegen_befund? }              // ← the back-edge. The club's audit trail, for free.

Ding { ding_id /*client-minted uuid*/, tent_id,
       art: 'pflanze'|'gabe'|'notiz'|'zettel'|'phase'|'mensch',
       name, t, t_end?, rel?: {an|in|betrifft: ding_id[]}, d?: {...},
       bilder?, akteur?, storniert_von?, created_at, edited_at? }

Bildwerte {                    // C14's FrameMetrics, ~200 B per captured frame
  image_id, device_id, timestamp, ok,
  verwurf?: 'licht_aus'|'transient'|'unscharf'|'doppelt'|'kamera_sprung',
  phash, helligkeit, schaerfe, gruenanteil?, kacheln: number[48],

Film { film_id, tent_id, von, bis, rezept_hash, pfad, bytes, dauer_s,     // metadata ONLY —

```

Projected read-time, never stored (C36's rule): `zelt`, `geraet`, `dose` (via `parseSocketRoles()`),
`kamera`, `bild`, `ziel` (`device.configuration` + `ZielVersion` + `Alarm[]`), `ereignis` (all of
`DeviceLog`), `regelsatz`. One read API, and the webapp consumes exactly it:
`GET /api/dinge?tent_id=&art=&von=&bis=&cursor=` · `GET /api/befunde?tent_id=&fenster=&format=json|csv`.

Load-bearing details:

- **The Kopfbefund is not a fixed widget.** It is whatever ranked first, rendered by the same Tafel
  renderer that a pushed Befund uses. If rank 1 is a camera finding, the body is the pair. If rank 1 is a
  photoperiod finding, the body is the light lane. If rank 1 is the Ruhebefund, the body is §4.2. **The
  home screen's shape is a function of the data, not of a layout decision.**
- The pair's endpoints come from the Kopfbefund's `belege.bildpaar`. Falling back, when the Befund has no
  image evidence: the newest *kept* frame (never a frame the cull rejected — the caption then reads
  `Bild verworfen (Hand im Bild) — gezeigt: 14:04`) and the newest kept frame at or before
  `localStorage['tc-zuletzt-<tent_id>']`, or `gestern gleiche Zeit` if that is under 4 h old.
- `Quittieren` writes `quittiert_von`/`quittiert_am`. The Befund does not vanish; it moves below the
  unacknowledged ones and its Zeile reads `quittiert von Ben, vor 10 Min`. In a club this is the single
  most useful line in the product.
- `Im Zelt` lists exactly the sockets `hardwareInfo.sockets` reports via `parseSocketRoles()`. Missing key
  (old firmware) fails **closed** to monitor-only with one Zeile: `Gerät meldet keine Steckdosen —
  Firmware zu alt.` This kills the live bug where `deviceControlCapability()` returns `'full'` for a
  heater-only tent and offers it a dehumidifier alarm preset.

### 4.1 The one screen shape (every Ding, no exceptions)

```
Kopf          Rangzeichen · Name · Status · Zeit/Spanne · Alter
Körper        art-specific. THE ONLY PART THAT VARIES.
Abhilfe       0–4 rows. Befunde only.
──────
<Verbindung>  first relation section; its German word is a function of the Subjekt's art:
              zelt→„Im Zelt"  befund→„Belege"  pflanze→„Steht in"  dose→„Steckt in"
              gabe→„Ging an"  bild→„Zeigt"  ziel→„Gilt für"  mensch→„Macht mit"
Befunde       ← THE REVERSE WALK. Which findings cite this Ding. Rendered only when non-empty.
Offen         open Zettel touching this Ding.
Verlauf       time-ordered history, cursor-paginated.
Werte         raw JSON + the literal GET + one copy button.
```

Navigation grammar, complete: **tap a Zeile → it becomes the Subjekt.** The previous Subjekt reappears as
a Zeile in the new screen's first relation section. Back returns. One gesture, no others.

**Streak framing is deliberate.** `Ruhig seit 3 Tagen` gives the daily visitor something that changes daily
on a screen whose honest content does not. It is the fix for C14's admitted weakness #1.

## 5. NO-MODES MECHANISM

The falsification test: **if you can name a control whose sole effect is to show or hide a class of
feature, it is a mode.**

**M1 · Rang ist Tiefe.** The Subjekt is fully rendered; everything else is 48 px. On the home screen the
Subjekt is *whatever ranked first*. No expand control, no density preference, no "mehr anzeigen", no
remembered expansion. You do not set depth; the ranking sets it and you walk from there. The impaired user
reads one finding and stops; the techie taps four times and is standing on a `ziel` Ding reading its change
history. **Same operation, same objects, nobody profiled.** Neither C14 nor C36 could produce this alone.

**M2 · Jeder Beleg ist ein Ding.** Depth is unbounded — Befund → Messfenster → chart → raw series → CSV —
and no control exists whose job is to reveal; you press the thing you are curious about. Because evidence
rows are Dinge the walk is reversible, and the reverse direction exists too (`Befunde` on every Ding).

**M3 · Pause ist die Geste** (C11, adapted). The Schieber's ▶ sweeps the Befund's window; tapping the frame,
▮▮, or simply stopping a drag unfolds §9.4's panel. Nothing persisted, no key, no preference; it
self-cancels on ▶; it hides no feature class, because it is *the data about the instant you point at*. A
state you never chose, cannot get stuck in, and that reverses with the identical gesture is not a mode.

**M4 · Reveal by capability.** Sockets per role, not per bucket. CO₂ rows only with the SCD4x. No camera →
no `kamera` Ding, no `bild` Zeilen, no film, no image Befunde, Verlaufsband instead of a pair (§11).

**M5 · Reveal by data.** Zero `pflanze` Dinge ⇒ the word "Pflanze" appears in exactly one place: the `+` on
`Im Zelt`. One `mensch` ⇒ no `Wer?` row, no attribution, no double-feed warning — **the club feature *is*
the second name.** One device ⇒ "Zelt" means the device and `+ Gerät in dieses Zelt` does not render.

**M6 · Two registers, one DOM node** (C14). Every Befund row is a prose line (17 px / 600) and a value line
(14 px / tabular-nums). The prose must be true without the numbers; the numbers complete without the prose.
There is no "show values" toggle because there is nothing to toggle.

### Honest audit

| Suspect | Verdict |
| --- | --- |
| `still_bis` (snooze) | **The closest call.** Scoped to one Befund *instance*, prints its own expiry on the row (`still bis morgen 14:00`), visible to every club member, cannot be applied to a rule or category, refused by severity-2 findings. It hides one row, not a feature class. A hostile critic can still call it a hiding control and I accept that. |
| `Δ` chip on the pair | Not a mode — it changes how one image is drawn, at the level of pinch-zoom. |
| The Regelsatz Ding | Not a mode — a destination reached by tapping the sort line, present for everyone from install, changing no other pixel. |
| Film toggles (§9.3) | Parameters of an artefact being produced, like an export resolution — with the admitted weakness that `Ruhig stellen` is an expert affordance most users never touch. |

Nothing keys off who you are, a stored preference, or an onboarding answer. The shipping
`EXPERT_MODE_STORAGE_KEY = 'app-settings-expert'` (`webapp/src/app/util/ui-mode.ts`) is **deleted**, along
with `fridge-simple-settings` and `simple-alarms-card` — not renamed.

## 6. The rule set — the sixteen Regeln, and what each offers as Abhilfe

Deterministic, versioned (`regelsatz_version`), evaluated cloud-side on a 5-minute ticker per tent and on
demand at screen entry. **Every remedy row is precondition-gated: it renders only if the Ding it walks to
exists.** Where it does not, a `grenze` row states the limitation instead.

| # | Regel | Fires when | Abhilfe (rendered only when the precondition holds) |
| --- | --- | --- | --- |
| 1 | `ziel_abweichung` | measure outside `ZielVersion ± Toleranz` > 45 min in the window | `ziel_aendern` (target exists) · `dose_pruefen` (a socket with the matching role exists and its duty cycle is available) · `grenze` (naming the missing role) · `zettel` |
| 2 | `ziel_abweichung_nacht` | as #1, restricted to measured `out_light = 0` | as #1, targeting `night.*` |
| 3 | `photoperiode` | measured lights-on duration differs from `daynight` schedule by > 10 min | `dose_pruefen` (light socket) · `ziel_aendern` (`lights.limit`, `daynight.day`) · `grenze` (PWM only, no socket) |
| 4 | `dose_dauerlauf` | a socket on > 90 % of the window while its measure never reached target | `dose_pruefen` · `grenze` (undersized kit — stated, not diagnosed) · `zettel` |
| 5 | `geraet_offline` | gap > 10 min in inbound status | `zettel` · walk to the `geraet` Ding's uptime history |
| 6 | `kamera_still` | no `format:'jpeg'` stored for > 3 h while a camera is paired | `kamera` (walk to the camera Ding + test image) · `zettel` |
| 7 | `licht_stimmt_nicht` | `out_light > 50 %` for 15 min while frame brightness sits in the lights-off band, or the inverse | `dose_pruefen` (light socket) · `kamera` · `zettel` — **the strongest correlation payoff: neither the picture nor the data detects a failed contactor alone** |
| 8 | `bildaenderung` | tile change score > 90th percentile of the frame's own 14-day baseline | none — image findings are descriptive by construction. Walks to the Wischvergleich zoomed to the tile. |
| 9 | `wachstum` | `gruenanteil` trend over the window exceeds `σ₁₄` | none. Labelled `Blattfläche (Bildanteil)`, never cm, never "Wachstum" as a claim. |
| 10 | `mensch_ereignis` | any `gabe`/`notiz`/`phase` Ding in the window | walk to the entry. Always ranks top-3 — a human action outranks a wobble. |
| 11 | `fuetterung_faellig` | regime step due and no `gabe` since | `gabe` (opens the sheet prefilled at that step) |
| 12 | `doppelgabe` | two `gabe` Dinge on intersecting plants inside the guard window | walk to both, with both `auto_bild` frames side by side |
| 13 | `alarm_ausgeloest` | `Alarm.isTriggered` | walk to the `Alarm` Ding · `ziel_aendern` |
| 14 | `datenluecke` | Influx coverage < 80 % in the window | `zettel` · walk to the `geraet` Ding. Every dependent Befund is greyed and prints its coverage. |
| 15 | `zettel_offen` | an open `zettel` older than 7 days | walk to it · `Erledigt` |
| 16 | `ruhe` | none of #1–15 fired | §4.2 |

**Ranking, printed under the list.** Severity 2 (#5, #6, #13) always pins to the top, ordered by duration.
Otherwise `rang_wert = |Δ| / max(σ₁₄, σ_floor) + 2,0·(human event in window) + log₂(1 + Minuten_außerhalb/60)`,
where σ₁₄ is that measure's standard deviation over 14 days *at the same hour ±1 h*, and `σ_floor` clamps
per measure (Temperatur 0,4 °C · rF 2 pp · CO₂ 40 ppm · VPD 0,05 kPa). Computed once per screen entry;
**the order does not move while you look at it.** The Befund's Kopf prints its own reason:
`Warum ganz oben: Abweichung 2,4 σ · 4 Std 10 lang`.

**Dedupe.** `befund_key = sha1(regel + subjekt + fensterbucket)`. A finding that is still the same finding
says `seit 3 Tagen` on the same row instead of reappearing. This is what stops the list from becoming
twenty rows of the same night.

## 8. Diary, multi-plant, watering and fertilising

### 8.1 The diary is not a feature

The Zelt's `Verlauf` is the tent's diary; a `pflanze`'s is that plant's; a `mensch`'s is what that person
did. Same Zeilen, same renderer. "It does the diary keeping for you" means: `ereignis`, `bild`, `film`,
`phase`, `ZielVersion` changes **and every Befund** are written into the same list a human writes into — so
a user who logs nothing still opens a full diary, containing the findings, which is a record nobody else
keeps. **Every entry gets its picture automatically:** on write the server sets `d.auto_bild` = the nearest
*kept* frame within ±5 min. One Mongo lookup, zero user effort. **Multi-plant is untaxed:** `rel.an: []`
means the whole tent and is the default forever.

```
pflanze  d: { sorte?, medium_key?, regime_key?, topf_l?, quelle?: 'samen'|'steckling'|'gekauft',
              keim_t, ernte_t?, ernte_g?, entfernt_t? }   name: "A3 · Wedding Cake"  rel: { in: [zelt] }
         — renaming NEVER changes ding_id (today, renaming a lifecycleName forks the whole history)
phase    d: { stufe: DiaryLifecycleStage }   t / t_end   rel: { an: [pflanze…] }
gabe     d: { wasser_l, kannen?, kannen_l?, ec?, ph?, ec_basis?: 'absolut'|'plus_leitungswasser',
              ablauf_ph?, ablauf_ec?, produkte: [{ name, ml_pro_l, aus_regime }],
              regime_key?, schritt?, auto_bild? }         rel: { an: [pflanze…] }, akteur
notiz    d: { text }   zettel d: { text } t / t_end(null=offen), d.geschlossen_von   mensch d: {} (name only)
```

`DiaryLifecycleStage` gains `ernte` as a seventh stage — harvest is not a stage today, so "how did this grow
do" is unanswerable. Optional field, read-time normaliser, no migration tool. `convertEventsToGrowCycles()`
becomes a **one-time idempotent boot backfill** emitting `pflanze` + `phase` Dinge from historic
`diary-plant-lifecycle` rows; nothing is deleted, old `DeviceLog` rows keep projecting as `ereignis`.
**Server-side cursor pagination for `dinge` and `DeviceLog` is a v1 prerequisite** — the unbounded
`getDeviceLogs` cannot survive this.

## 9. Camera, timelapse, image correlation — and THE SLIDER

### 9.1 What exists, and the cull (C14's pipeline, and it is right)

`ffmpeg` is installed and invoked via `execFile`; `sharp` 0.34.5 and an ImageMagick wrapper are already
dependencies — **no new binary.** A frame lands every 30 s; rolling `1d`/`1w`/`1m` timelapses are built
hourly, 25 fps, `libx265 -crf 30`. `Image { data: Buffer }` (`server/src/models/images.model.ts:22`), no
GridFS anywhere.

### 9.2 Bildwerte per frame at ingest — two `sharp` decodes, ~9 KB of pixels, ≤ 60 ms

downscale → `licht` read from `out_light` in Influx at ts ± 60 s (**we own the lamp; no camera vendor can do
this**) → `helligkeit` → `schaerfe` (3×3 Laplacian variance) → `phash` (8×8 dHash, Hamming < 3 = duplicate)
→ `dx/dy` (integer SAD ±8 px, translation only) → `kacheln[48]` (8×6 mean absolute difference — the change
map: it says **where**, never **what**) → transient test (frame *t* is transient if d(t−1,t) and d(t,t+1)
are both > 4× the rolling median while d(t−1,t+1) < 1.5×; 30 s lookahead) → `gruenanteil`. Plus, free and
unavailable to competitors: **any frame within ±3 min of a human-authored `gabe`/`notiz`/`bild` is dropped,
because a human told us they were standing there.**

Explicitly refused as computer-vision fantasy: naming a drooping leaf, diagnosing a deficiency from colour,
measuring height in cm, counting plants, segmenting canopy, detecting pests. The product points at the tile
and shows the pair; **the human does the semantics.**

### 9.3 Der Film — and HOW IT IS STORED

**The mp4 does not go in Mongo.** `Image.data: Buffer` against a 16 MB BSON cap is why every concept in
this bake-off had to promise a 90-second film. Decision, made not deferred: **renders are written to a
`FILM_DIR` docker volume** and streamed with real `Accept-Ranges`; the `Film` document holds metadata and a
path only. A 12-week 720p x264 film at crf 21 is 12–20 MB — fine on disk, impossible in BSON. **GridFS is
the stated alternative if ops refuses a volume** (`film.pfad` becomes a GridFS id, one adapter); the volume
wins because streaming a Range out of a file is less code. The rolling `1d`/`1w`/`1m` stay in Mongo (small,
thinned, working) but are **re-encoded to x264** — `libx265` in mp4 does not play in Firefox anywhere or
Chrome on Linux/most Windows, so today's timelapse is invisible to a large share of the people who bought
the camera. Three flags, half a day, the highest-value change in this document.

```
ffmpeg -y -framerate 25 -f image2 -i %05d.jpeg \
  -vf "scale='min(1280,iw)':-2:flags=lanczos,format=yuv420p" \
  -c:v libx264 -profile:v high -level 4.0 -preset veryfast -crf 21 \
  -g 50 -movflags +faststart -metadata title="Terp Control – Zelt Keller · Tag 12–40" out.mp4

GET /film/:film_id.mp4?token=<imageToken>
  video/mp4 · Accept-Ranges: bytes · Content-Disposition: attachment;
  filename="zelt-keller_tag12-tag40_2026-10-14.mp4"      (ASCII-folded ä→ae, no device_id —
                                                          in a camera roll the filename is the label)
```

Three routes off the phone, feature-detected, and the UI says which one you get:
`navigator.share({files:[File]})` where supported (≤ 50 MB) → the file lands in WhatsApp/Telegram/Fotos
directly; `<a download>` on Android/desktop; on iOS without Web Share the video opens in a tab under one
line, *„Lange drücken → In „Fotos" sichern."* The `?token=` URL is the existing 30-day image token, so **a
pasted link plays with no login** — a share that produces a login wall is not a share.

The Film Ding's Körper shows the **cull report** — the product's honesty made visible, and the one thing
that explains why this film is watchable when the competitor's is not:

```
Was drin ist                                    ☑ Nur Tagbilder
  4 121 Bilder aufgenommen                      ☑ Helligkeit angleichen
    − 1 084 Licht aus   − 121 Hand im Bild      ☑ Ruhig stellen
    −    88 unscharf    −  22 Kamera verrutscht ☑ Zahlen einblenden
  = 2 806 Bilder → 112 Sek bei 25 B/s
  2 Kapitel (Kamera verrutscht am 12.09.)
```

Normalisation per kept frame via `sharp.linear()` toward the film's own median channel means, with the
per-frame change clamped to ±8 % — that temporal clamp is the deflicker and it is three lines.
Stabilisation applies accumulated integer `(dx,dy)` via `sharp.extract()` on a 96 % window; **rotation is
not corrected** — a sustained residual cuts to a new `Kapitel` captioned `Kamera verrutscht · 12.09.`
Burn-in reuses `imageService.addOfflineOverlay`'s SVG-composite technique: bottom-left
`Tag 24 · 14:02 · 24,1 °C · 58 % rF · VPD 1,21`, bottom-right `💧 Anna · 6,0 l` when a Gabe falls within
10 min. Two camera alarms are created the moment a camera is paired, reusing `Alarm` storage and
`handleAlarmAction` but needing their own ~80-line evaluator ticker (`alarm.service` only evaluates on
inbound MQTT `StatusMessage`): `kamera_still` (#6) and `licht_stimmt_nicht` (#7).

### 9.4 THE SLIDER — Der Beleg-Schieber

**What it scrubs: the Befund's own evidence window.** Not a film, not a calendar — the span the finding is
about, `t → t_end`, with `jetzt` marked as `◆` when the window is still open. On the Zelt Tafel it scrubs
the *comparison window*, whose left edge is the `VORHER` frame.

```
  ◂──────●═══════════════════════════════════◆──────▸
    Beginn    Phasenwechsel     gestern      jetzt        ← snap ladder, 44 px magnetic zones
  ▓▓▓▓▓▓▓▓▓░░▓▓▓▓▓▓▓▓▓▓▓▓░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓     ← behalten ▓ / verworfen ░ / Lücke ·
                                       [ ▶ ]  [ Δ ]
```

**One cursor, four projections** (`CursorService`, a `BehaviorSubject<number>` — the strip, the pair, the
chart lane and the Befund body are all rendered from it):

| Move this | These move with it |
| --- | --- |
| drag the strip | the `VORHER` frame · the Kopfbefund's value line · the chart cursor (if `/verlauf` is open) |
| tap a thumbnail | the cursor jumps to that instant; the value line and the frame follow |
| tap a Beleg row | the cursor jumps to that evidence's timestamp and the strip scrolls to it |
| `Nächster Moment über 20,5 °C →` in the pause panel | the strip and the frame jump to the next excursion |

Correlation runs in both directions, which is the owner's actual ask.

**A rule that protects the impaired user: rows never reorder while the thumb is down.** During a drag the
Befund list keeps its identity and order and only the value lines update. On release the order settles
with a 200 ms crossfade and the sort line prints `neu sortiert`. A list that rearranges under a finger is
unusable at 2 a.m.

**Pause ist die Offenlegung.** Tap the frame, or ▮▮, or simply stop dragging, and the instant under the
cursor unfolds downward — in place, below the pair:

```
        [ Bild 24.08. 03:41 ]
  ╭──────────────────────────────────────────────╮
  │ 24.08.2026 03:41 · Tag 24 · Blüte            │
  │                                              │
  │ Temperatur   20,5 °C   Ziel 20,0    +0,5   ▲ │  ← tap a row = that series, this window
  │ Luftfeuchte  61 %      Ziel 55 %    +6     ▲ │
  │ VPD          1,08 kPa  Band 1,2–1,5  −0,12 ▲ │
  │ CO₂          412 ppm   Ziel 400      +12   ○ │  ← only with the SCD4x
  │                                              │
  │ Ziel galt seit 12.08., gesetzt von Ben     ›  │  ← from ZielVersion, NOT today's config
  │ Lief: Heizung an seit 02:10 · Licht aus      │  ← only sockets that exist
  │ Tagebuch ±2 Std: Gabe 6,0 l (Anna, 19:40)  ›  │
  │                                              │
  │ Bild: belichtet ×1,04 · Schärfe 0,71 ·       │  ← the techie's floor, always present
  │       behalten · Kachel 3/6 am stärksten     │
  │ [ Nächster Moment über 20,5 °C → ]           │
  ╰──────────────────────────────────────────────╯
```

Nothing is persisted, no `localStorage` key, no preference. It self-cancels on ▶. It hides no feature
class — it is the data about the minute you are pointing at. **`Ziel galt seit 12.08.` is the line only
this concept can print**, because targets are versioned Dinge (§3) — every other concept in the round
shows today's setpoint against last month's measurement and calls it a delta.

Header behaviour: a **pinned scrub header**, never a floating tooltip. There is no hover on touch.

**v1 delivery of the strip:** thumbnails through the existing `?width=160` resize (N requests,
`max-age=3600`, HTTP/2 — survivable at 40 tiles). A sprite+index endpoint
(`GET /streifen/:tent_id?von&bis&n=50`, one JPEG + `[{t,x,y}]`, 24 h TTL) is v1.1 and is what makes it feel
instant on tent wifi.

Not a theme — a rhythm. Everything reuses the existing `--tc-*` tokens
(`webapp/src/theme/variables.scss:113-133`); no new hex anywhere.

**Baseline grid 4 px.** Section padding 16, gutters 12, card radius `--tc-radius-md` (12), section gap 20.
Touch targets never below 44 px; a Zeile is 48 px; the Schieber's thumb is 44 px with a 12 px visual.

**Type scale — five steps, and there are no others.** Zahl groß 32/700 tabular-nums `-0.02em` (the Befund's
headline delta, the gauges) · Titel 22/700 (Tafel Kopf) · Prosa 17/600 (the Befund's prose line, Zeile
names) · Wert 14/500 **tabular-nums** (every value line) · Beiwerk 12/500 `--ion-color-medium` (ages, snap
labels, `Warum ganz oben`, uppercase section headers at `.12em`).

**Every number is tabular-nums.** A value line that shifts by a pixel as it counts is the difference
between a scrub that feels mechanical and one that feels broken.

**Colour carries one meaning only: severity.** `▲` = `--tc-text-warning` (schwere 1) or `--tc-text-danger`
(schwere 2) · `●` = `--tc-text-info` (a human or machine event) · `○` = `--ion-color-medium` (ruhig).
`--tc-text-success` is reserved for `im Ziel` and the primary action. The `Δ` tile tint is
`--ion-color-warning` at 35 %. Nothing else in the product is coloured. The 12 px status square is filled
when fresh, hollow when stale (2–10 min), grey when offline — the number is never removed to make room for
the verdict; the verdict is the square.

**Empty-state illustration** — exactly one, and it is data, not a cartoon: the Ruhebefund's
**Ruhestreifen**, a 24 px row of one bar per day of the streak, height = that day's time-in-band, colour =
the severity that day reached. Three quiet days look like three tall green bars. Drawn from the same
numbers the Belege list, so it cannot lie; degrades to a single bar on day one. Day-one screens use no
illustration at all — a sentence and a waiting indicator.

## 15. Honest weaknesses

1. **The remedy catalogue is the whole bet, and a wrong remedy is worse than none.** `Nachtziel anheben` is
   right when the heater is oversized and wrong when the tent is in a hot loft. Precondition gating stops
   nonsense rows rendering; it does not make the remaining rows correct. That a remedy is always a *walk to
   something inspectable* is real mitigation — and an admission that I made advice navigable, not solved.
2. **The σ normaliser hides real excursions.** A noisy tent has a large σ₁₄, so a genuine excursion sinks.
   `σ_floor` is a fudge, visible the moment two tents are compared.
3. **Findings need history, so week one is thin**, and a competitor's busy dashboard still *feels* more
   valuable on day two while telling you less.
4. **`still_bis` is the closest thing to a mode here** and my §5 defence is not airtight.
5. **The rule engine is a real cost.** 16 rules × a 5-min ticker × N tents touching Influx and Mongo, on top
   of `Bildwerte` (~50 ms × 2 880 frames/device/day ≈ 6 CPU-h/day at 150 devices) and the ffmpeg poll —
   against one pm2 process with `pLimit(10)`. The `befund_key` cache is the only thing between this and a
   melted server; it needs a real queue and probably a second box before the series sells out.
6. **Tabless means the film is two taps away** — a bet on C36's discipline that will annoy exactly the
   customer who paid the camera premium. And **"4 Befunde" reads as "4 problems"** even when three are
   `○ gleich`; I have no data on where the give-up threshold sits.
7. **`gruenanteil` is a weak growth proxy** (leaf angle, dimming, defoliation, camera shift; near-noise
   under magenta LED) and it is the headline visual metric. **The cull's 60-second blind spot is invisible
   by construction** — users see removals only as a count.
8. **`ZielVersion` backfills from incomplete `DeviceLog` config-diff rows.** Charts before the boundary draw
   a flat historical target with a printed caveat — honest, and still a gap in the history a long-run grower
   cares about. Likewise, I designed the tent merge and not the un-merge.
9. **This is a looking surface, not a steering surface.** Changing a night target is three taps where
   today's form is two; the `Ziele` Tafel's inline `value-edit-row`s are a partial climb-down toward a
   settings page and a critic will correctly call it that.
