# C59 — "Gegenüberstellung"

**Fusion of:** C14 (das Paar) · C36 (das Ding) · C11 (der geteilte Regler)
**Centre of gravity:** comparison is a verb applied to any two things, and it is the only screen shape.

---

## 1. Thesis

**Every screen is two things next to each other with one shared needle running through both, and the app's
job is to name what is different at the position the needle stands on.** Not "the camera compares two
frames". *Gegenüberstellen* is one operation behind one component and it takes any two Dinge of the same
kind: zwei Durchgänge, zwei Pflanzen, zwei Tage, zwei Dosen, diese Woche und letzte Woche, zwei Menschen im
Club, zwei Bilder — and **dein Ist und dein Ziel**, the pair that exists on day one when nothing else does.
So the screen is a seam down the middle, a thing on each side, a slider under both, a sentence on the seam.
Drag the slider and the sentence rewrites itself. One vocabulary, learned once.

C14's discipline holds and is extended: **the app describes differences and, where a deterministic rule
over data it already owns permits, names the one thing under the user's control that differs from a
reference that worked.** It never diagnoses a plant. It does say *„Beim letzten Durchgang stand das
Nachtziel auf 18,0 °C."* — because it recorded that, and because comparison is what makes that possible.

---

## 2. What comes from where — and the fusion

**From C14 — das Paar.** Two things side by side, the difference named in one German sentence. Right half
is the subject, left is what you hold it against. Prose line and number line are one DOM node, two
registers, no toggle. Ranking deterministic, sort key printed. Describe, never diagnose.

**From C36 — das Ding.** One kind of object: a name, one time (`t`, optional `t_end`), a body, named German
relations. One Zeile shape, one Tafel shape. Depth is reached by walking a relation, never by switching a
mode. `Werte {…}` on every screen shows the exact `GET` that produced it. Capability and data decide what
exists; a preference never does.

**From C11 — der geteilte Regler.** One playhead, many projections, marked `jetzt`. Drag the bar, the
chart, or tap a thumbnail — all write the same cursor; correlation runs both directions. **Pause is the
disclosure gesture:** tapping the frame stops playback and unfolds that position — measured vs target vs
delta, sockets that ran, diary entries within ±2 h, the frame's exposure verdict. Nothing persisted,
self-cancels on play, hides no feature class. Pinned scrub header, never a tooltip.

### THE FUSION

**Die Naht: one cursor that is relative to each half's own life, so a single drag lands on two different
wall-clock moments.**

C11's playhead is one absolute timestamp. Put two Dinge side by side (C14) where both are the same shape
with their own `t`/`t_end` (C36) and the cursor stops being a timestamp: it becomes **a position inside a
span**, which projects onto *each* half separately. Drag to `Tag 24`: the left half shows 14. Juli, the
right half 3. Oktober. One needle, two clocks. Three consequences no single source produces:

1. **The axis is derived from the Art, never chosen from a menu.** Two `durchgang` → *Tag im Durchgang*.
   Two `tag` → *Uhrzeit*. Two `woche` → *Wochentag + Uhrzeit*. Two `bild` (no span) → the cursor
   degenerates into C14's Wischvergleich handle. C36 guarantees both halves are the same Art, so the axis
   is a property of the pair, and the app prints it: `Achse: Tag im Durchgang`.
2. **C14's one sentence becomes a function over the cursor.** C14 named the difference between two
   endpoints once. Here it is recomputed at every position, so the pair has a **Differenzkurve**, and
   `‹ Nächster Unterschied ›` becomes a real button. C11's *„Nächster Moment über 30 °C →"* generalises.
3. **A Gegenüberstellung is itself a Ding** — name (`Durchgang 3 gegen Durchgang 2`), time, body (two
   sides + axis + cursor), relations (`links`, `rechts`) — so it is saved, listed in the Verlauf, shared,
   exported and re-opened at the exact position you left, on machinery C36 already built. **That is why it
   never feels like a database query: a comparison is a thing you made, and it lives in the diary next to
   your photos.**

Remove C14: no pair, no difference sentence, no describe-don't-diagnose discipline. Remove C36: the
operation applies to camera frames only — a feature, not a product. Remove C11: two static endpoints
again, no needle, no difference curve, no pause-to-unfold.

## 3. Information architecture

A **Zelt** sits above the device — the brief's missing entity — and is the scope root.

```
/list                       Deine Zelte  (one zelt → straight through, as today)
/z/:zelt_id                 HOME. The Zelt as Subjekt, always a pair.
/z/:zelt_id/:ding_id        any Ding as Subjekt, always a pair
   ?gegen=<ding_id|ziel|vorher>   left half     ?bei=<0..1>   cursor
   ?achse=<tag|uhrzeit|datum|wochentag>
/z/:zelt_id/chart?…         the chart      /z/:zelt_id/g/:g_id   a saved Gegenüberstellung

kept, redirecting, query string passed through untouched:
/device/:id/diary → /z/:zelt_id      /device/:id/charts?<q> → /z/:zelt_id/chart?<q>
/device/:id/settings → UNCHANGED for fan·light·plug·dryer;  → /z/:zelt_id/ziele for controller·fridge
/device/:id/testmode, /shares, /account, /classes, /demo, /login   untouched
```

Three screens exist: the Zelt list, the pair, the chart. Everything that is a page today is a Ding under
the Zelt — settings are `ziel` Dinge, the diary is the Zelt's `Verlauf`, the grow report is a `durchgang`
Tafel, maintenance is a `zustand`. **Share links need no schema change:** `ShareLink.query` already stores
a query string (`shared-types/index.d.ts:86`) and the whole comparison lives there, so *„diese Stelle
teilen"* is the existing machinery with a longer `query`. `ShareLink.page` stays `'charts' | 'diary'`.

```ts
interface Ding {          // ONE new MongoDB collection: `things`
  ding_id: string;        // uuid v4, MINTED BY THE CLIENT (offline idempotency, §8)
  zelt_id: string;  device_id?: string;  art: Art;  name: string;
  t: number;              // ms epoch — EVERY Ding has one time
  t_end?: number | null;  // explicit null = still open (a running Durchgang)
  rel?: Record<string, string[]>;   // { an, in, links, rechts, betrifft }
  d?: Record<string, unknown>;  bilder?: string[];
  akteur?: string;          // ding_id of a `mensch`
  storniert_von?: string;   // corrections, never hard edits
}
type Art = 'zelt'|'durchgang'|'pflanze'|'dose'|'kamera'|'bild'|'film'|'streifen'
         | 'gabe'|'notiz'|'zustand'|'phase'|'ziel'|'mensch'|'ereignis'|'gegenueberstellung';

zelt      d: { device_ids: string[], tz: string }
durchgang d: { nummer, medium_key?, regime_key?, schritt? }   t = Tag 1, t_end = null while running
ziel      d: { schluessel: 'day.temperature', wert: 25.0, vorher: 24.0, quelle: 'nutzer'|'preset' }
```

**Stored:** `zelt`, `durchgang`, `pflanze`, `gabe`, `notiz`, `zustand`, `phase`, `mensch`, `ziel`,
`gegenueberstellung`. **Projected read-time:** `dose` (`parseSocketRoles(hardwareInfo.sockets)`), `kamera`
(`hardwareInfo.webcam_did`), `bild`/`film` (`Image`), `ereignis` (`DeviceLog`), `streifen` (§9).

**`ziel` fixes the brief's missing setpoint history.** Every accepted config push writes one `ziel` Ding
with `vorher` + `wert` — one insert on a path that already runs. Non-negotiable: a comparison drawing
today's target over last July's data is the lie this concept sits on. Historic values backfill from
`DeviceLog` config rows once, at boot, idempotently. **Zelt migration:** on first boot every claimed device
with no Zelt gets `zelt { device_ids:[device_id] }`; four devices in one room are merged in `Zelt → Geräte`
(two taps, one array push). `durchgang` hangs off the **Zelt**, so one grow across four boxes is one diary
and **one day counter**.

## 5. NO-MODES MECHANISM

> **Test:** if you can name a control whose sole effect is to show or hide a class of feature, it is a mode.

**N1 — there is no single view to switch back to.** **Every Ding renders as a pair, always**, because the
left half has a fallback ladder that always terminates (§12): *das vorige gleichartige Ding → dasselbe Ding
früher → dein Ziel*. Day one compares the tent to its own targets; week nine to last week. Nothing was
switched on and there is no "normal mode" to return to. The fusion does the work: C36's uniformity
guarantees a left half exists, so C14's pair is not a feature but the frame.

**N2 — pause is the disclosure gesture** (C11, generalised). Tap either frame → playback stops and the
position unfolds downward, under the seam:

```
   Tag 24 · Sa 13.09. 03:12    gegen    Tag 23 · Fr 12.09. 03:12
 ╭────────────────────────────╪───────────────────────────────╮
 │ Temperatur   20,5 °C       │  +2,4 K      18,1 °C          │
 │   Ziel       18,0 °C  +2,5 │              18,0 °C   +0,1   │
 │ Luftfeuchte  58 %          │  +1          57 %             │
 │ VPD          1,15 kPa      │  −0,03       1,18 kPa         │
 │ Lief: Licht aus, Heizung   │              Licht aus        │
 │       an 51 Min            │                               │
 │ Tagebuch ±2 Std: Gießen    │              —                │
 │       2,0 l (Anna, 19:40)  │                               │
 │ Bild: belichtet ×1,04      │              ×1,02            │
 │       scharf 0,71 behalten │              0,74 behalten    │
 │ Abhilfe: Die Heizung lief nachts 51 Min. Das Nachtziel     │
 │ steht auf 20,0 °C — beim Durchgang davor auf 18,0 °C.      │
 │ [ Nachtziel auf 18,0 °C stellen ]      [ Rohdaten ]        │
 ╰────────────────────────────────────────────────────────────╯
```

Not a mode, and C11's four reasons survive the port: nothing persisted (no `localStorage`, no preference,
no onboarding question); the identical gesture reverses it in under 200 ms and `▶` self-cancels it; it
hides no feature class — it is *the data about the position you are looking at*, and the stoner reads three
rows while the techie reads eleven; the gesture is inherited from every video player on earth.

**N3 — capability and data, never a preference.** `Im Zelt` lists exactly the sockets
`parseSocketRoles(hardwareInfo.sockets)` reports; a humidity `ziel` **is not created** unless a
`dehumidifier` role is paired, killing the live bug where `deviceControlCapability()`
(`grow-presets.ts:143-173`) returns `'full'` for a heater-only tent. A missing key (old firmware) fails
**closed**: `Gerät meldet keine Steckdosen — Firmware zu alt.` Zero `pflanze` Dinge ⇒ "Pflanze" appears in
one place only, the `+` on `Im Zelt`. One `mensch` ⇒ no `Wer?` row. No camera ⇒ no frames, no film, no
`streifen`. None of it is reversible by a setting. `EXPERT_MODE_STORAGE_KEY` (`webapp/src/app/util/
ui-mode.ts`) is **deleted**, not renamed.

| Suspect | Verdict |
| --- | --- |
| `Achse: Uhrzeit` chip | **The closest call.** Derived from the pair's Art, *printed rather than hidden*, tapping it pushes a new Gegenüberstellung (back works, nothing stored), and both axes expose the identical feature set — no row, chart, action or number exists on one and not the other. It changes what is plotted, at the level of pinch-zoom. A hostile critic can still call it a view switch and I will not pretend otherwise. |
| `[ Gegenüberstellen ]` · `Was noch anders ist` | Not modes — the first is navigation (a route with a different `?gegen=`; every screen it reaches is reachable by tapping a Zeile), the second is one complete list ordered by a printed key, unchanged rows included and marked `○ gleich`, nothing behind a "mehr". |
| `Werte {…}` · ⟡ gemerkt | Not modes — same row same position every screen from install; one held object, visible, dismissible, changing no pixel but one suggestion in the next picker. |

**The picker — you never pick two things.** You are always already standing on one. **(a)
Gegenüberstellen**, one action on every Tafel; sheet title `Wogegen?`, body is **Zeilen** — the same 48 px
row shape as everywhere else, never a form, never a type picker, never a date range. Top rows computed and
named in German prose:

Only Dinge of the same Art appear. No type select, no filter panel, no operator, no date pickers unless the

## 6. The chart — `/z/:zelt_id/chart`

ECharts 6, tree-shaken, hand-rolled ~50-line directive (owner decision); `chart.js`/`ng2-charts`/
`chartjs-adapter-luxon` deleted in the same commit. The chart is the pair drawn on an axis: **one panel per
measure, two series per panel, and the seam becomes a fill.**

```
│   │  ▓▓▓▓ Differenzfläche, vorzeichenbehaftet ▓▓▓▓       │  ← THIS is the comparison
│ Luftfeuchte %  ·  VPD kPa                (eigene Panels) │

├──────────────────────────────────────────────────────────┤
│ Im Ziel  91 % │ 84 %     ·   Nacht 71 % │ 62 %           │  verdict, across the seam
│ längste Abweichung  41 Min │ 2 Std 10 (Nacht, zu warm)   │
└──────────────────────────────────────────────────────────┘
```

- **Goal vs actual per side**, one source at a time, labelled, in priority: the user's own
  `Alarm.upperThreshold`/`lowerThreshold` (ignored by the chart today) → `Sollwert ± Toleranz` (±1,5 °C /
  ±7 % rF, the tolerances `grow-assistant-card` already uses) → `GROW_STAGE_PRESETS.vpdRange`, VPD only.
- **The Sollwert is stepped and comes from the `ziel` history** (§3), not today's `device.configuration` —
  the error this concept cannot survive, so that write is a prerequisite, not a feature.
- **Tag/Nacht** per side from measured `out_light > 0`, `daynight` as fallback, device timezone in the axis
  label; a failed contactor is a *missing band*, a diagnostic rather than decoration.
- **Ausgänge** as state-timeline lanes; region length = duration, null = gap, never 0/1 lines. The
  `Entfeuchter` region carries the truth on tap: `In den Betriebsarten „temp" und „breed" kühlt diese Dose,
  sie entfeuchtet nicht.` `sampling:'minmax'` on the primary series (LTTB smooths away the bang-bang
  oscillation the grower wants); LTTB for the navigator. One finger scrolls, two pan/zoom, tap sets cursor.
- **Verdict computed server-side on raw Influx samples**, never `aggregateWindow(mean)`; split Tag/Nacht;
  longest excursion as a duration; greyed below 80 % coverage with coverage printed. **Prerequisite:**
  parameterise the raw Flux interpolation of `measure`/`from`/`to`/`interval` (`data.service.ts:80-89`),
  move `limit(n:50000)` before `yield()`, constrain interval by timespan.

## 7. Diary and multi-plant

**There is no diary feature.** A Zelt's `Verlauf` is the tent's diary, a `pflanze`'s is that plant's, a
`durchgang`'s is that run's — same Zeilen, same renderer, cursor-paginated by `t` (server-side pagination
is a prerequisite; today's unbounded `getDeviceLogs` cannot carry this). "It does the diary keeping for
you" is operational: `ereignis`, `bild`, `film`, `phase`, `ziel`-changes and `gegenueberstellung` are
written by the machine into the list the human writes into, so a user who logs nothing opens a full diary.

```ts
pflanze  d: { sorte?, medium_key?, topf_l?, quelle?: 'samen'|'steckling'|'gekauft',
              keimung_t, ernte_t?, ernte_g?, entfernt_t? }
         name: "A3 · Wedding Cake"    // renaming NEVER changes ding_id — the round-one bug where
         rel: { in: [durchgang_id] }  // renaming a lifecycleName forks the history is gone
phase    d: { stufe: DiaryLifecycleStage }  t / t_end  rel: { an: [pflanze…] }  // [] = whole tent
gabe     d: { wasser_l, kannen?, kanne_l?, ec?, ph?, ec_ort?: 'zulauf'|'ablauf'|'tank',
              ablauf_ph?, ablauf_ec?, produkte: [{ name, ml_pro_l, aus_regime: boolean }],
              regime_key?, schritt?, auto_bild? }   rel: { an: [pflanze…] }, akteur, bilder
notiz    d: { text }                     rel: { an: [...] }, bilder
zustand  d: { text, geschlossen_von? }   t / t_end(null = offen), akteur
mensch   d: {}                           name only, Zelt-scoped, no account
```

`DiaryLifecycleStage` (`shared-types/index.d.ts:107`) gains a seventh value `ernte`; harvest is not a stage
today, so "wie ist dieser Durchgang gelaufen" is literally unanswerable. Optional field, read-time
normaliser, no migration tool.

**Every entry gets its picture automatically** (C14): on write the server sets `d.auto_bild` to the nearest
kept frame within ±5 min. One Mongo lookup; it turns a text log into a visual record and it is what lets
the double-feed guard show soil rather than words (§8). **The plant-ignorer is untaxed:** `rel.an: []`
means the whole tent and is the default forever — no empty state, no "0 Pflanzen" card, no nag.
`convertEventsToGrowCycles()` (`grow-report.component.ts:691-747`) becomes a one-time idempotent boot
backfill emitting `durchgang` + `phase` Dinge, then is deleted from the browser; legacy `DeviceLog` rows
keep projecting as `ereignis`/`notiz` through a read-time adapter, seven English-prose regexes included.

**The cumulative question**, answered on the `pflanze` Tafel — and, being a pair screen, answered *against
something*:

```
Bisher in dieser Blüte              A3 (Durchgang 3)  │  A3 (Durchgang 2)
  Wasser                                 18,5 l / 11  │  22,0 l / 14
  Bio-Bloom                              31 ml        │  44 ml        −13 ml
  von                          Anna 7 · Ben 3 · ich 1 │  Anna 14
```

**The guard is the concept in miniature:** it does not argue, it holds Anna's frame next to the live frame
across the seam so you can see whether the soil is dark — words → evidence, at the cost of one lookup,
because `d.auto_bild` already exists. Windows: water 6 h, feed 18 h, per-medium (coco 3 h / 12 h, where
several daily feeds are correct), owner-editable.

| Path | Sequence | **Taps** |
| --- | --- | --- |
| Routine water, prefilled | `Gießen` → `Speichern` | **2** |

Same sheet, same field order, every time. The 2-tap and the 15-tap paths differ only in how far down the
user chooses to go — C14's register argument applied to a form.

**Medium + Regime, chosen once**, on the `Durchgang` Tafel, the way a grower says it out loud:

```

  (•) Biobizz All-Mix + Bio-Grow/Bio-Bloom       Vorgedüngt — Düngen ab Woche 3–4

  ( ) BioTabs                                    Kaum Flüssigdünger — neue Tabs alle 4–6 Wochen
  ( ) Kein Schema — ich trage selbst ein
  Zuletzt geprüft: 12.08.2026 · Quelle: Herstellerplan

Regime { regime_key, medium_text, feedline_text, start_ab_woche,
         schritte: [{ index, anker: 'woche'|'gabe_n', produkte: [{ name, ml_pro_l, range? }],
                      ec_ziel?, ec_basis: 'absolut'|'plus_leitungswasser', ph_range? }],
         quelle_url, geprueft_am, art: 'herstellerplan'|'herstellerrechner'|'herstellerlos' }
```

A Mongo content collection, **never in the webapp bundle**; brand names as plain text only, no logos, no
brand colours, never inside a Terp Control feature name; `quelle_url` + `geprueft_am` surfaced as
`zuletzt geprüft 12.08.2026` — legal posture and a genuine trust feature in one string. The engine advances
**by feed events** (`Schritt 7 von 14`) with a soft calendar mapping, because growers feed Tue/Fri and
slip. Before `start_ab_woche` the sheet prefills **no products** and shows the one line where the product
refuses to fill something in: `All-Mix ist vorgedüngt — bis Woche 3 nur gießen.` Every prefilled value
stores `aus_regime: true`, flipped to `false` the moment the user edits it, so the report says `wie im
Plan` vs `abweichend` months later — the club's actual question. EC is canonical mS/cm;
`ec_basis:'plus_leitungswasser'` renders as `EC-Ziel 1,4 + dein Leitungswasser`, never a bare ppm.
Autoflower gets a `×0,25–0,5` multiplier and no 12/12 flip.

**Double-logging** is killed by construction: the client mints `ding_id` before the request, the server
upserts on `{zelt_id, ding_id}`, so a replay is idempotent. v1 has no service worker — a failed save is
held in `localStorage`, retried on app focus, rendered `⏳ noch nicht gespeichert`. That is not
capture-in-a-cellar and the release notes say so.

## 9. Camera, timelapse, image correlation — and THE SLIDER

**Cull and metrics at ingest:** two `sharp` decodes plus plain JS on ~9 KB of pixels, ≤ 60 ms/frame.
`sharp` 0.34.5, ffmpeg and an ImageMagick wrapper are already dependencies (`image.service.ts:16,28,502`) —
no new binary, no ML runtime.

| Step | How | Honest limit |
| --- | --- | --- |
| `licht_an` | `out_light` from Influx at ts ±60 s | cross-modal and correct — the payoff of owning the lamp |
| `helligkeit`, `schaerfe` | mean grey; variance of a 3×3 Laplacian on 128×96 | cannot tell fog from a defocused lens; reported `unscharf`, never as a cause |
| `phash` · `versatz_dx/dy` | 8×8 dHash (Hamming < 3 = duplicate); integer SAD ±8 px vs a running reference | dedup only; **translation only** — a rotated camera is detected (residual stays high) and becomes a Kapitel break, not a correction |
| `kacheln[48]` | mean abs. difference per tile of an 8×6 grid | says **where**, never **what** |
| transient | d(t−1,t) and d(t,t+1) both > 4× rolling median while d(t−1,t+1) < 1,5× | catches a hand or a door; **blind to anything over 60 s** |

**Refused as computer-vision fantasy at every version:** naming a drooping leaf, diagnosing a deficiency
from colour, height in cm, counting plants, segmenting canopy, detecting pests. Instead: point at the tile
and show the pair. *The human does the semantics.*

Two cloud-side alarms are created the moment a camera is paired, reusing `Alarm` storage and
`handleAlarmAction` with their own ~80-line ticker (`alarm.service` only evaluates on inbound MQTT):
`webcam_silence` — *„Zelt Keller: Die Kamera hat seit 3 Std kein Bild geliefert."* — and `light_mismatch` —
*„Zelt Keller: Das Licht sollte an sein, das Bild ist dunkel."* The second proves the correlation thesis:
neither picture nor data detects a failed contactor alone; together they do, in fifteen minutes.

### How the film is stored

1. **Frames** — `Image {format:'jpeg'}` as today, thinned on the existing schedule, retention 90 days,
   stated in the UI.
2. **`streifen` (sprite sheets) — what the slider actually scrubs.** One JPEG sprite per (Ding, tier),
   rebuilt nightly with `sharp`: run tier = 1 tile per grow-day at 256×144 (84 days ≈ 600 KB), day tier =
   1 tile per 10 min (144 tiles ≈ 900 KB). An ordinary Mongo document with a `kacheln` index array —
   **~1 MB, nowhere near the 16 MB BSON limit** — served `Cache-Control: private, max-age=86400`. A
   twelve-week comparison is two requests and scrubs at 60 fps offline. **The slider never needs an mp4.**
3. **Films — GridFS, in v1.** `server/src` has no GridFS today; the fix is `new GridFSBucket(conn.db,
   {bucketName:'films'})` from the `mongodb` driver mongoose already bundles — **no new dependency, no new
   infrastructure, ~1 day**, and the 16 MB cap is gone. A `film` Ding holds metadata plus `d.gridfs_id`;
   the route pipes `bucket.openDownloadStream(id)` with `Accept-Ranges: bytes` (required, or iOS Safari
   will not play it inline). Twelve weeks at 12 fps, 1280×720, crf 23 ≈ 6–10 MB, uncapped. **Refusing
   GridFS is what caps the flagship artefact at 90 seconds; it is one day of work and it ships.**

Encoding `libx264 -profile:v baseline -level 3.1 -pix_fmt yuv420p -crf 23 -vf scale=1280:-2 -movflags
+faststart`. Today's pipeline encodes **`libx265`** (`image.service.ts:583`), which iOS Photos, WhatsApp
and Chrome will not play — today's timelapse is invisible to most customers who own one. Both encodes
switch to H.264 in v1: two lines, and the highest-value two in this document.

**The export only this concept produces: a side-by-side film.** `ffmpeg -i links.mp4 -i rechts.mp4
-filter_complex hstack -c:v libx264 …`, seam drawn, halves captioned `Durchgang 2 · Tag 24` /
`Durchgang 3 · Tag 24` by the SVG-composite technique proven in `imageService.addOfflineOverlay`
(`image.service.ts:127-158`). Filename `terpcontrol-zelt-keller-durchgang3-gegen-2-tag1-84.mp4`,
ASCII-slugged. Off the phone by `navigator.share({files:[File]})` where supported → straight into
WhatsApp/Telegram/Fotos; `<a download>` on Android/desktop; on iOS without Web Share the video opens in a
tab under `Lange auf das Video tippen → „Video sichern".` A `?token=<imageToken>` URL plays for 30 days
with no login.

### The slider

**Die Naht-Regler.** Pinned under the pair, full width, 56 px tall, 44 px thumb, on every pair screen.

**What it scrubs: the relative position along the pair's own axis**, not a wall-clock timestamp. Both ends
carry real values (`Tag 1` … `Tag 84`, or `00:00` … `23:59`). The playhead is labelled `jetzt` **only when
the right half's `t_end` is null** — a finished Durchgang has no `jetzt` and the slider does not invent one.

**What moves with it — one cursor, N projections:** both camera frames (from the two `streifen`, so it is
instant and works offline) · both film strips either side of the seam, themselves scrubbable · every delta
chip · the difference sentence · both charts, output lanes and annotation rails on `/chart` · the pinned
scrub header. **Never a hover tooltip; there is no hover on touch.** Everything writes one
`VergleichCursor` (`BehaviorSubject<number>`: position in [0,1] plus the axis) — drag the bar, drag either
chart, tap a thumbnail in either strip, and every projection renders from it. Correlation runs both
directions, now across two timelines at once. The cursor is in the URL as `?bei=`, so `[ Diese Stelle
teilen ]` is the existing share machinery.

**Jump buttons, both directions.** `‹ Nächster Unterschied ›` walks the Differenzkurve to the next position
where any measure's normalised delta exceeds the printed threshold; `Nächster Moment über 30 °C →` survives
verbatim from C11 as a long-press on the same control. **`▶` plays the comparison:** both halves advance in
lockstep, two grows growing side by side in sync, Tag 1 to Tag 84, 12 fps, entirely from the sprite sheets.
That is the demo. **Pause unfolds** §5's panel under the seam — nothing persisted, self-cancels on `▶`.

**The other correlations.** Every event carries its frame (`d.auto_bild`); every number drills into
`/chart` with the span applied; tapping any frame makes that `bild` the Subjekt — full size, the readings
at that instant, the setpoint *in force at that instant* from the `ziel` history, any event within ±30 min.
`kacheln[]` summed per frame is a `Bildänderung` series in Mongo needing no Influx allowlist change:
metrics ship in v1, the chart lane in v1.1.

## 10. Clubs — attribution without an auth rewrite

- A `mensch` Ding is Zelt-scoped, named once by the owner, and **has no account**; every capture writes
  `akteur`. ~2 days, no change to `auth.middleware.ts`. The `Wer?` row renders only with ≥ 2 `mensch`
  Dinge — a solo grower never sees it. Free text (`Vorname oder Spitzname reicht`); identity never
  requested. **Attribution is a label, not a gate**, and the release notes say so. Upgrade path designed
  in: a later real account sets `mensch.d.user_id` and every historic row keeps resolving.
- **Zettel** (`zustand`) is the note taped to the tent door: opened by anyone, closed by anyone with `✓`
  stamping `d.geschlossen_von` + `t_end`. A slim amber strip **above the pair** — the only element allowed
  to outrank the picture, correctly, because a human wrote it for another human.
- **Corrections, not edits.** Editing a `gabe` writes a new one with `storniert_von`; the old Zeile renders
  struck through. Reconstructable history without cryptographic immutability, which would victimise the
  unregulated grower.
- **The club-native comparison: `Anna gegen Ben`.** Two `mensch` Dinge are the same Art, so the general
  operation applies with no new code: what each logged, how much water, which products, at what EC, over
  the run, on one axis across one seam. Nobody built this because nobody generalised the pair.
- **Privacy, maximal by default.** Harvest weight and plant count **never prompted** (`ernte_g` starts
  empty, labelled `optional`). No location, no analytics SDK, no community feed; frames and films carry a
  token. Retention stated: frames 90 days, sprites with them, films until deleted. **One-tap `Alle Daten
  dieses Zeltes löschen`** actually deletes `things`, `Image`, `films.*`, `DeviceLog` and the Influx
  series, fixing the standing lie where `DELETE /device/logs/:device_id` removes nothing because `deleted`
  is a visibility flag (`device.service.ts:739`). **Refused outright:** per-member dispensing, grams handed
  over, member identity, date of birth. § 26 KCanG is the club's system of record, not ours.
- **Reaching a closed app.** The server has `sendMail` and webhooks only — no push, no service worker. v1
  adds one thing that works: a **Telegram destination** as an alarm `actionType` — bot token, chat id,
  ~150 lines, no service worker, no APNs, no store review, reaches a locked phone. Web Push (VAPID +
  `@angular/service-worker`) is v1.1 and named as such. v1 also ships **one `x-api-key` per account**
  (`server/src` has none) over `GET /api/things` plus NDJSON export — the C36 `Werte` payoff and the
  brief's missing bulk export, ~1 day.

## 12. Day one and the first 48 hours

Comparison needs two things and day one has one. Designed for, not apologised for.

**Die Vorher-Leiter — printed, deterministic, always terminating.** The left half resolves down this ladder
and the screen names the rung it landed on:

| Rung | Condition | Left half is | Label shown |
| --- | --- | --- | --- |
| 1 | a previous Ding of the same Art exists | that Ding | `Der Durchgang davor` |
| 2 | this Ding has ≥ 24 h of its own history | itself, one span earlier | `Gestern` / `Letzte Woche` |
| 3 | the user has looked before | newest keeper at `localStorage['tc-zuletzt-<zelt_id>']` | `Als du zuletzt geschaut hast` |
| 4 | **always** | **the targets in force** | `Dein Ziel` |

Rung 4 is the fusion's gift: **Ist gegen Soll is a Gegenüberstellung**, so the pair is never empty and day
one is not a broken week nine — it is the same screen showing the one comparison that always exists. Chips
read `20,5 °C ── +2,5 ──► Ziel 18,0 °C`, the sentence reads *„Es ist 2,5 °C wärmer als dein Nachtziel."*,
and the slider scrubs the 24 h you have. **Hour 0**, device claimed and nothing else: the left frame is the
empty-state SVG (§4) with one line, `Noch nichts zum Danebenhalten. Bis dahin steht dein Ziel links.`, and
Verlauf holds one Zeile, `◼ Gerät verbunden · vor 4 Min`. No onboarding card, no hero, no wizard, no "what
kind of user are you". Then, with real timestamps computed from `now`:

```
Was noch kommt
  ✓ Zahlen                seit 4 Min          ◷ Gestern         morgen 14:02
  ✓ Ziel als Vergleich    sofort              ◷ Der Tagesfilm   morgen früh
  ◷ Erstes Bild           in ~30 Sek          ◷ Letzte Woche    Sa 20.09.
```

Six lines, no illustration: a promise the app then keeps, which is what a first session is for. Rows
disappear as each rung arrives and the block is gone by day 8. With < 1 frame of history no delta is
fabricated against a synthetic zero — values carry `Erste Messung` and the seam shows `—`, not `+0,0`.

## 14. Saying what to do — the remedy rules

Deterministic, rule-based, over data the app already owns. **No AI advisor, no plant diagnosis.** A remedy
renders only when a rule fires; when none fires there is no remedy line and the screen does not pretend.
Each rule names one thing under the user's control and offers exactly one action.

| # | Fires when | German | Action |
| --- | --- | --- | --- |
| 1 | measure outside band > 2 h **and** a socket role that moves it the right way is paired **and** that socket did not run | `Zu warm seit 3 Std 10. Die Heizung war aus — das ist nicht die Ursache. Prüfe Abluft und Zelttemperatur.` | `[ Verlauf zeigen ]` |
| 2 | measure outside band > 2 h **and** the responsible socket ran the whole time | `Der Entfeuchter lief 4 Std durchgehend und es bleibt zu feucht. Die Dose schafft das Zelt nicht.` | `[ Ziel anpassen ]` |
| 3 | target unreachable — no socket role can move the measure in the needed direction | `Für „Feuchte 50 %" fehlt die Dose. Du hast keinen Entfeuchter angelernt.` | `[ Dose anlernen ]` · `[ Ziel entfernen ]` |
| 4 | the measure was in band at this position in the previous Durchgang **and** a `ziel` differs | `Beim Durchgang davor stand das Nachtziel auf 18,0 °C. Jetzt steht es auf 20,0 °C.` | `[ Auf 18,0 °C stellen ]` |
| 5 | `out_light > 50 %` for 15 min while frame brightness sits in the lights-off band | `Das Licht sollte an sein, das Bild ist dunkel. Prüfe Dose 3 (Licht).` | `[ Dose testen ]` |
| 6 | measured photoperiod differs from the `daynight` schedule by > 15 min for 3 days | `Das Licht lief 25 Min länger als geplant — 12 Std 25 statt 12 Std 00.` | `[ Zeitplan zeigen ]` |
| 7 | regime step due and no `gabe` since | `Fütterung fällig — Schritt 5, seit 2 Tagen.` | `[ Gießen ]` prefilled |
| 8 | no frame for > 3 h with a camera paired | `Die Kamera hat seit 3 Std kein Bild geliefert.` | `[ Kamera prüfen ]` |
| 9 | device offline > 10 min | `Zelt offline seit 24.08., 14:20. Die Zahlen unten sind von da.` | `[ Verlauf zeigen ]` |

Rule 4 is the one only this concept can write and the strongest: **the advice is „do what you did last
time", and the app can say it only because comparison is a first-class operation and setpoint history is
recorded.** Not a model, not a heuristic, not a claim about plants — the user's own successful
configuration, retrieved. Device writes are disabled while offline, reason printed: `Gerät offline —
Änderung wird bei Rückkehr gesendet.`

## 15. Honest weaknesses

1. **The axis chip is a view switch and a critic will say so.** Derived from the Art, printed, pushed as a
   route, storing nothing — but `Tag im Durchgang` vs `Datum` changes the screen, and my defence rests
   entirely on it hiding no feature. The softest joint in the concept.
2. **Comparison is genuinely wrong for user type 1 most days.** He wants the number and gets it with a
   `+0,1` chip beside it and a seam he did not ask for. Two 168 px frames on a 390 px phone is a small
   picture where C11 gave him a full-bleed one.
3. **Two runs are rarely comparable and the app will imply they are.** Different strain, pot, season, lamp
   height. `Tag 24 gegen Tag 24` invites a conclusion the data cannot support, and the honest disclaimer is
   a line nobody reads. I have made C14's describe-don't-diagnose temptation bigger, not smaller.
4. **The Vorher-Leiter is a hidden dependency.** Which rung fired changes what the sentence means. I print
   the label and that is thin — a fast reader absorbs `+2,4 K` without absorbing what it is +2,4 K *against*.
5. **Sprite sheets are a second copy of the images and go stale.** A nightly rebuild leaves the newest
   tiles up to 24 h behind; I patch the tail from live frames, so two code paths render the same strip.
6. **`ziel` history has no history before the deploy.** The `DeviceLog` backfill is partial and lossy, so
   rule 4 — my best rule — is silent for every existing customer's first comparison. The feature that sells
   the concept starts empty.
7. **Comparing two Menschen is socially loaded.** `Anna gegen Ben` is one tap from a shared login and it is
   a scoreboard in a room where people volunteer. I ship it because clubs asked "who did what"; my only
   mitigation is keeping it off the home screen.
8. **CPU is a real cost.** ~50 ms of `sharp` per frame × 2 880 frames/day/device, plus nightly sprite
   builds and film renders, against one pm2 process with `pLimit(10)`. This needs a real job queue and
   probably a second box before the first series sells out.
9. **The tent merge is a data model the user must understand** — the one place in the product where he has
   to think about the schema. I doubt a better answer exists without a firmware room field.
10. **Most days, nothing is different.** The honest answer is a flat seam and `○ Nichts Auffälliges`. A
    competitor's busy dashboard *feels* more valuable while telling you less. Rung 4 does not fix that.
