# C16 — "Sendefertig"

**Family:** camera · **Centre of gravity:** the app's output is a finished, shareable object — and the
paths out of the product are designed, not assumed.

---

## 1. Thesis

**Terp Control does not show you data; it manufactures objects — a clip, a card, a week sheet, a bundle —
and every screen in the app is the live preview of the object you would send right now.**

Every other concept in this bake-off ends at the glass. The grower looks, understands, closes the app.
Sendefertig says the looking is the by-product and the *object* is the product: an mp4 that plays in a
Telegram group, a 1080×1350 PNG with the numbers burned into it, a Markdown block with hot-linked images
that pastes into a forum, a ZIP the club treasurer opens in Excel. The controller already takes a still
every 30 seconds and already knows the temperature at that second. Nobody has ever turned that pair into
a file a person can hold.

This inverts the usual build order. Instead of "design a dashboard, add a share button later", the export
render is designed first and the screen is defined as its preview. That has one enormous consequence for
the round's hard problem: **the depth you read the object at is the same axis as the format you export it
in.** The stoner and the techie are not two users of one screen; they are two *reading depths of one
object*, and the object carries all depths at once whether or not anyone opens them.

Named honestly: this is a concept about distribution. It will be attacked for optimising posting over
growing. See §13.

## 2. Information architecture

Five destinations. No tab bar is added — the existing `ion-menu` + `ion-split-pane` stays; a device
switcher is added to the header because the artifact shelf is per-device.

```
/list                        Device list. One device → straight to /device/:id
/device/:id                  DIE KARTE — home. The live artifact preview + the shelf + ranked rows.
/device/:id/film             DER FILM — the frame axis: strip, chart, ledger. Correlation lives here.
/device/:id/buch             DAS BUCH — events, plants, conditions, feed regime, cumulative sheets.
/device/:id/ausgaben         AUSGABEN — every artifact ever rendered, its exits, its recipients.
/device/:id/einstellungen    Unchanged settings (existing ngSwitch per device_type).
/a/:artifact_slug            PUBLIC. No login. One artifact + its data ribbon. og:image.
```

Navigation between them: a four-item segmented rail pinned under the header on every device page —
`Karte · Film · Buch · Ausgaben`. Not a mode switch; each is a different *object* (now, over time, what
happened, what left). `/a/:slug` is the only route outside `AuthGuard`, guarded by a `ShareLink` with
`page: 'artifact'`.

**The one new persisted concept the whole IA hangs on:**

```ts
Artifact {
  artifact_id: string; slug: string;          // 'k7m2p' — 5 chars, URL-safe, per device
  device_id: string; cycle_id?: string;
  kind: 'clip' | 'card' | 'week' | 'bundle';
  from: number; to: number;                    // the span it covers
  spec: ArtifactSpec;                          // everything needed to re-render it, verbatim
  status: 'queued' | 'rendering' | 'ready' | 'failed';
  data?: Buffer;                               // ≤14 MB, see §13.3
  mime: 'video/mp4' | 'image/png' | 'application/zip';
  bytes: number; width?: number; height?: number; durationSec?: number;
  filename: string;                            // exactly what lands in the download folder
  frameCount?: number; culledCount?: number;
  sidecar: object;                             // the machine-readable depth. Always present.
  createdAt: number; createdBy?: string;
  sends: { at: number; via: 'download'|'telegram'|'discord'|'webhook'|'link'|'copy' }[];
}
```

An Artifact is immutable. Re-rendering with a changed spec makes a new one. That is what makes the
"who did I send what" question answerable, and it is what makes the public link stable.

## 4. NO-MODES MECHANISM — the object carries every depth, and depth is the export format

The mechanism has one sentence: **every card in this app is a preview of a file, and pulling the card
open shows you the file's own sidecar.** There is no second interface, because there is no second object.

### 4.1 The gesture

`⌄ Details` under the card. It is always visible, always labelled in words, never a preference, never
remembered as a setting. Tapping it expands the card downward in place. Tapping it again collapses it.
It is the *same control on the same object* in all four screens, so learning it once is learning it
everywhere.

```
Depth 0   the card:  a picture, three numbers, one bar, one age.
          ↓ ⌄ Details
Depth 1   the band, unpacked into every value that produced it:
            Temperatur     24,1 °C   Ziel 25,0 · Abweichung −0,9 · Messung 12:41:07
            Luftfeuchte    58 %      Ziel 55 · Abweichung +3
            VPD            1,12 kPa  Blattversatz −2,0 K (angenommen, kein Blattsensor)
            Im Ziel        87,2 %    von 1.412 Rohwerten, Abdeckung 98,4 %
            Licht          an seit 06:00 · out_light 100 %
            Bild           14:41:07 · 1920×1080 · 214 kB · behalten
          ↓ ⌄ Rohdaten
Depth 2   the sidecar itself, as a table and as raw JSON, with the exact Influx query,
          the exact image_id, the frame-ledger verdict for this frame and its neighbours,
          and a [ Als JSON kopieren ] / [ Als CSV laden ] pair.
```

### 4.2 Why this is not a mode

A mode is a persistent state that changes what a *different* screen shows. This changes nothing but the
height of one card, it resets when you leave, and — the load-bearing part — **Depth 2 is not a view, it
is the export.** Every artifact this product renders ships `sidecar`, and the sidecar is byte-identical
to what Depth 2 displays. So:

| The user | picks the exit | and thereby picks a depth |
| --- | --- | --- |
| stoned, 2am | `⤓ Sichern` | Depth 0 — the PNG or the mp4 |
| posting to a forum | `Als Markdown kopieren` | Depth 1 — the numbers are in the text |
| the club's record-keeper | `Auszug laden` | Depth 2 — CSV + JSON, the whole ledger |
| a Home Assistant user | `Webhook` | Depth 2 — the sidecar is the POST body |

Nobody is asked what kind of user they are. Nobody is denied a number. The techie's "give me the raw
series" and the sharer's "give me the file" are answered by the same code path at different truncations,
which is exactly why one interface can carry both without splitting.

### 4.3 Ranked density carries the rest

Below the card, the rows are ordered by |actual − target| normalised per measure, then by recency of
change, then by a fixed tiebreak order (temp, RH, VPD, CO₂, light, outputs). Everything is present; the
ordering is the filter. **Rows never reorder while the screen is open** — the order is computed on
navigation and frozen, because an impaired user must be able to tap the row they saw a second ago. It
re-ranks only on entry or pull-to-refresh, which is a deliberate act.

### 4.4 Reveal by capability and by data (used, not invented)

- The card's band shows CO₂ only if `hardwareInfo` reports the SCD4x. Not greyed — absent.
- The Gießen sheet shows a plant picker only when ≥ 2 plants exist.
- The actor picker appears only when `cloudSettings.actors.length > 1`.
- `Clip rendern` appears only when ≥ 60 kept frames exist in the span.
- The feed line appears only when a `feedRegime` is selected; otherwise Gießen is only water.

## 5. The chart — inside DER FILM, and it is an axis for pictures

The chart is not a page here. It is the lower half of `/film`, sharing one x-axis and one cursor with the
film strip above it. ECharts 6 (owner decision), hand-rolled directive, `grid[]` + `axisPointer.link`.

```
┌─ DER FILM ────────────────────── Tag 41 ─┐
│ ▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮ │  film strip: one sprite per window,
│ ▲                          ░░░ ▮▮▮ ░░░  │  gaps drawn as gaps (░ = no frame)
│ 12:41 · 24,1 °C · 58 % · 1,12 kPa       │  the pinned scrub header (no hover tooltip)
├──────────────────────────────────────────┤
│ Temperatur °C                            │
│  ╌╌╌╌╌╌┐         ┌╌╌╌╌╌╌  Soll (gestuft) │  dashed stepped setpoint from day/night config
│ ▒▒▒▒▒▒▒│░░░░░░░░░│▒▒▒▒▒▒▒  Zielband      │  markArea, from alarm thresholds if set,
│ ───────┴─────────┴────────  Ist (min/max)│  else setpoint ± tolerance, else stage vpdRange
├──────────────────────────────────────────┤
│ rF %              (same construction)    │
├──────────────────────────────────────────┤
│ VPD kPa   band moves with the stage      │
├──────────────────────────────────────────┤
│ Ausgänge  ▬▬▬▬▬  ▬▬  ▬▬▬▬▬▬  Licht       │  state-timeline lane, region = duration

├──────────────────────────────────────────┤
│ Ereignisse  ● ● ●●    ▲        ●         │  annotation rail, 2 rows max, clustered
│             Gaben     Stufe   Notizen    │  at 10 px bins with count badges
└──────────────────────────────────────────┘
```

- **Day/night** is a `markArea` band per panel, derived from measured `out_light > 0` where present,
  falling back to the configured `daynight` schedule, in an explicit named timezone. A failed contactor
  shows as a *missing band* against the schedule ghost — a diagnostic, not decoration.
- **Goal vs actual**: dashed stepped `Soll`, solid `Ist` drawn as a min/max envelope
  (`aggregateWindow` min + max, `sampling:'minmax'`), and a signed deviation fill *between the two lines*
  — never to the axis.
- **Annotations**: every `Event` in §7, plus device logs. Full-height dashed lines for stage changes.
  Tapping a cluster opens the events at Depth 1 in a sheet; each has `Diesen Moment als Karte` which
  renders an Artifact at that timestamp.
- **The correlation is the cursor.** One `timeCursor$: BehaviorSubject<number>` in
  `CameraCorrelationService`. Scrubbing the strip moves the chart cursor; scrubbing the chart moves the
  displayed frame; tapping an event moves both. `frameAt(t)` = nearest `Image{format:'jpeg'}` within
  ±90 s; `dataAt(t)` = nearest Influx point within ±5 min, else `—` plus the age.
- **Everything on this screen is exportable at the current window.** The header carries `⤓` which opens
  the share sheet with the window pre-filled: `Clip 14.–21. Mai`, `Karte 21. Mai 12:41`,
  `Auszug 14.–21. Mai`.

## 6. The diary and multi-plant — DAS BUCH

The diary is the caption track of the film. New collections (Mongo, cloud-side, all fields optional per
the no-migration-tooling rule; `DeviceLog` is left alone and keeps carrying device events):

```ts
Plant {
  plant_id; device_id; cycle_id?;
  name: string;                       // 'A1'
  strain?: string;                    // plain text
  startedAt: number; archivedAt?: number;
  medium?: string;                    // 'biobizz-all-mix'
  cropRect?: { x:number; y:number; w:number; h:number; validFrom:number }[];  // v1.1
}

Cycle { cycle_id; device_id; name; startedAt; endedAt?; stage: DiaryLifecycleStage; flipAt?: number }

Event {
  event_id; device_id; cycle_id?;
  plantIds: string[];                 // [] means "the whole tent" — this is the untax
  type: 'water'|'feed'|'note'|'photo'|'stage'|'training'|'condition'|'harvest'|'measure';
  at: number;
  actorId?: string; actorName?: string;
  water?: { taps:number; canLitres:number; litres:number; perPlant:boolean };
  feed?:  { regimeId?:string; stepIndex?:number;
            items:{ name:string; mlPerL:number }[];
            ec?:number; ph?:number; litres:number; source?:'zulauf'|'ablauf' };
  measure?: Partial<DiaryEntryData>;  // the five old fields still land here
  text?: string; imageIds?: string[]; frameId?: string;
  clientEventId: string;              // UUID minted at tap. Server upserts on it.
  supersedes?: string;                // corrections are new rows, never edits
  deletedAt?: number;
}

Condition { condition_id; device_id; text; openedBy?; openedAt; closedBy?; closedAt? }
```

**How a user who ignores plants is untaxed.** There is no plant onboarding step, no "add your first
plant" empty state, no plant column in any list until a Plant row exists. `plantIds: []` is the normal
case and reads as `Zelt` everywhere. The card says `Tag 41` from the Cycle, not from a plant. The film is
the tent's. A user can run three cycles and never learn the word Pflanze. When they *do* create a second
plant, a compact `A1 A2 A3` chip row appears in the Gießen sheet and a per-plant filter appears in Das
Buch — and nowhere else.

**Migration of what exists:** `convertEventsToGrowCycles()` becomes a one-time idempotent backfill in the
service constructor, writing `Cycle` rows from historical `diary-plant-lifecycle` logs. The five legacy
entry types map onto `Event.type` (`diary-measurement` → `measure`, `diary-plant-log` → `note`,
`diary-co2-refill` → `note` with text, `diary-plant-lifecycle` → `stage`). Old rows stay in `DeviceLog`
and are read-merged; nothing is rewritten in place.

**"It does the diary keeping for you"** — the artifact framing pays this off directly. Das Buch's default
view is not a list of rows; it is a **week ledger**, one row per week, each one already rendered as a
sendable Wochenbericht. The user's typing is optional garnish on a record the device wrote.

## 7. Watering & fertilising — the tap count is the datum

No irrigation hardware exists. So this is a capture-speed and recall problem, and the capture must survive
a dark tent and one hand.

**What is stored.** `water: { taps: 3, canLitres: 0.5, litres: 1.5, perPlant: false }`. The **taps are the
primary datum** and the litres are derived, because taps are what the human actually did. If the user
later corrects the can size to 0.6 L, past events keep their recorded `canLitres` — history is not
retroactively rewritten, and the club can see that Tuesday's 3 cans were measured with a different can.

**Feeding.** With a regime selected, the sheet prefills:

```
   Dünger   Bio-Grow      2,0 ml/L   [−][+]
            Bio-Bloom     2,0 ml/L   [−][+]
            Bio-Heaven    1,0 ml/L   [−][+]
            = 3,0 ml Bio-Grow in 1,5 L
   Schritt 7 von 13 · Blüte Woche 3
   EC 1,4   pH 6,2       [ gemessen? ]        ← optional, collapsed
```

Every prefilled number is editable in place. Deviating is one tap, not an error state.

**Schedule following, three rules:**
1. The regime advances by **feed events**, not by wall clock. `stepIndex = count of type:'feed' events in
   this cycle`. A grower who feeds Tue/Fri and slips a week is not thrown off.
2. The **12/12 flip is detected from `out_light` history** — the first day the measured photoperiod drops
   below 13 h for three consecutive days sets `Cycle.flipAt`, which anchors the bloom-relative index.
   No bottle brand's calculator can do this; the controller can.
3. **Medium + feed regime is one selectable thing**, labelled the way it is said: `Biobizz All-Mix`,
   `Biobizz Light-Mix`, `Floragard Light`, `Green House Powder Feeding`, `BioTabs`, `Eigenes Schema`.
   All-Mix therefore *has* a "don't feed yet" phase and expresses it as a real step, not as a note.

**Regime storage:** a Mongo content collection `FeedRegime { regime_id, label, medium, source_url,
retrieved_at, chart_version, kind, steps[] }` — never bundled into the webapp, so one brand is removed
with one DB update. `Zuletzt geprüft: 12.03.2026` renders under the picker as a trust feature.

**Reminders (the "thinks for me" face):** if the regime's step cadence and the last feed event imply a
gap > cadence + 24 h, a row appears on the card: `Gabe fällig — zuletzt vor 5 Tagen  [ Jetzt ]`. That row
is data-driven, not a setting, and it disappears when satisfied.

**Cumulative recall (the club face):** Das Buch → `Verbrauch` renders a table per plant per cycle:
litres, ml per product, by actor, with a `Als CSV` exit. `Wie viel Bio-Bloom hat A3 bekommen?` is one tap.

**Cellar capture:** every event mints a `clientEventId` UUID at the moment of tap and the sheet closes
optimistically. The outbox lives in `localStorage` and flushes on reconnect; the server upserts on
`clientEventId`, so replay can never double-log. This is honestly *not* a service worker (see §12) — it
survives a reload and a lost connection, not a killed browser.

## 8. CAMERA, TIMELAPSE AND IMAGE CORRELATION — the headline

### 8.1 What ships in v1: a clip someone can actually hold

Today the server builds three rolling timelapses (`1d`/`1w`/`1m`) hourly with ffmpeg at 25 fps,
`libx265 -crf 30`, from frames thinned to a fixed interval, stored as `Image{format:'mp4'}`. It is real
machinery and it works. Three things make it unshippable as an artifact, and v1 fixes exactly those.

**(a) The codec cannot leave the building.** `libx265` in an mp4 is HEVC. It does not decode in Firefox,
it is unreliable in Chrome on Android, and Telegram's in-app player will not touch it. Every export
renders **H.264 High profile, `yuv420p`, `-movflags +faststart`**, which plays everywhere including a
2019 phone. Rolling previews may stay HEVC to save storage; **anything with an exit path is H.264.**
This costs roughly 1.4–1.8× the bytes at equal quality and it is not optional.

**(b) The content is garbage without culling.** See 8.2.

**(c) There is no file.** See 8.4.

### 8.2 The frame ledger — culling, with a number for every rule

At capture (or lazily at first render), each jpeg gets one small row. `sharp().stats()` already returns
per-channel `mean`, plus `entropy` and `sharpness` — the detector is nearly free, and `sharp` 0.34.5 is
already a dependency, as is `ffmpeg`.

```ts
FrameMeta {
  device_id; image_id; timestamp;
  lightOn?: boolean;         // out_light > 0 at t (Influx), else the daynight schedule
  meanY: number;             // 0..255
  meanR, meanG, meanB: number;
  sharpness: number;         // sharp stats.sharpness
  dHash: string;             // 64-bit difference hash of a 9×8 greyscale reduction, hex
  shiftFromPrev: number;     // hamming distance to the previous KEPT frame, 0..64
  verdict: 'keep'|'dunkel'|'ueberstrahlt'|'unscharf'|'doppelt'|'stoerung'|'manuell';
  reason?: string;
}
```

Rules, applied in order, each producing a named verdict — **nothing is ever deleted, only marked:**

| # | Rule | Threshold | Verdict |
| --- | --- | --- | --- |
| 1 | Lights off | `lightOn === false`, or `meanY < 25` when `out_light` is unavailable | `dunkel` |
| 2 | Door open / daylight flash / IR flare | `meanY > 240` **or** `meanY > 2.5 ×` the trailing 30-frame median | `ueberstrahlt` |
| 3 | Condensation, fog, defocus | `sharpness < 0.45 ×` the trailing 24 h median | `unscharf` |
| 4 | Someone in the tent | `shiftFromPrev > 14` **and** the frame ±3 slots later returns to within 6 of the pre-event hash | `stoerung` |
| 5 | Nothing happened | `shiftFromPrev < 3` **and** the slot already has a kept frame | `doppelt` |
| 6 | **Camera nudged** | `shiftFromPrev > 14` and it does **not** revert within 20 frames | `keep` + a `shift` marker |

Rule 6 is deliberately not a cull. A nudged camera is a fact the viewer must see, so the clip gets a
**chapter boundary** there and the film screen shows `Kamera am 12.05. bewegt`. v1 does not stabilise; it
marks. Claiming otherwise would be a lie about 12 weeks of drift.

**Honesty about rule 4:** this is transient-change detection with a friendly name, not person detection.
An oscillating fan swinging a leaf into frame will occasionally be culled as `stoerung`. It is named this
way in the ledger (`stoerung` = disturbance, not `person`) and the ledger is one tap away on any frame.

### 8.3 Normalisation — why 12 weeks of frames become one watchable clip

Three passes, all inside the existing "write frames to a temp dir as `%d.jpeg`, then run ffmpeg" shape,
so this is an insertion into a working pipeline rather than a new one.

1. **Cadence resample (the pass nobody in round one named).** Source cadence is 30 s when online and
   nothing when offline, so a raw clip plays at wildly varying real-time speed and the viewer cannot read
   it. Every export resamples to a **fixed wall-clock slot** — 10 min for a week clip, 30 min for a
   12-week clip — and per slot picks the highest-`sharpness` kept frame nearest the slot centre. An empty
   slot **holds the previous frame** by default; the option `Lücken als Schwarzbild` inserts a black frame
   captioned `kein Bild · 14. Mai · 3 Std`. Either way the gap is drawn on the strip. Time becomes linear,
   which is what makes growth legible.
2. **Exposure and white balance.** For each kept frame compute the target from a 9-frame rolling *median*
   of the clip's own `meanY` / channel means (median, not mean, so a single blown frame does not drag the
   whole neighbourhood). Apply per-channel linear gain with `sharp().linear([gR,gG,gB],[0,0,0])`, gains
   clamped to `0.6 … 1.6` and channel ratios clamped to ±20 % so a genuinely dark frame is not amplified
   into noise and magenta LED is pulled toward neutral without inventing colour. The gain series itself is
   median-smoothed over 9 frames so the clip does not pulse. *(Verify `sharp.linear` accepts arrays on
   0.34.5; the fallback is `.recomb()` with a diagonal matrix.)*
3. **Crop to a common rectangle** when a `shift` marker exists: all frames in a chapter share the
   chapter's own frame size; chapters are concatenated rather than reframed. No warping.

Cost: for a 12-week clip at 30-min slots that is ~4,000 frames × (one sharp read + one linear write). On
the existing `pLimit(10)` box, measured against the current pipeline's per-frame work, budget 3–6 minutes
per long render. That is why rendering is a **job**, not a request (§8.4).

### 8.4 How a video LEAVES the product

The gap the camera critic named. Concretely:

```
POST /artifact/:device_id
  { kind:'clip', from, to, opts:{ hud:true, nightFrames:false, slotMinutes:10,
                                  maxBytes: 8_000_000, aspect:'9:16' } }
  → 202 { artifact_id, slug, status:'queued' }

GET /artifact/:artifact_id            → the Artifact doc (status, bytes, filename, sidecar)
GET /artifact/:artifact_id/file       → the bytes, Content-Disposition: attachment; filename="…"
GET /a/:slug                          → the public page (ShareLink page:'artifact'), no login
GET /a/:slug/file                     → the bytes, hot-linkable, Cache-Control: public, max-age=31536000
```

**Format and filename, decided not hand-waved:**

| kind | container | codec / format | size | filename |
| --- | --- | --- | --- | --- |
| `clip` | mp4, faststart | H.264 High, yuv420p, 25 fps, CRF chosen to hit `maxBytes` | 1080×1920 (9:16) or 1920×1080 | `terp-zelt-keller-tag-28-bis-41.mp4` |
| `card` | png | sRGB | 1080×1350 | `terp-zelt-keller-tag-41.png` |
| `week` | png (v1) / pdf (v1.1) | sRGB | 1240×1754 | `terp-zelt-keller-woche-6.png` |
| `bundle` | zip | — | — | `terp-zelt-keller-woche-6.zip` |

`maxBytes` is a real design input, not decoration: **Discord's free attachment cap is 10 MB and Telegram's
bot video cap is 50 MB**, so the share sheet sets `maxBytes` from the chosen destination *before*
rendering, and the encoder does a two-pass bitrate calculation to land under it. If a span cannot fit, the
sheet says so in advance: `Woche 1–12 passt nicht in 8 MB. Vorschlag: 720p oder 30-Min-Takt.`

**The five exits, all designed:**

1. **`⤓ Sichern`** — an `<a href download>` at `/artifact/:id/file`. On Android this lands in Downloads and
   the media scanner surfaces it in the gallery. **On iOS Safari it lands in Files, and the user must then
   "In Fotos sichern".** The sheet says that, in those words, on iOS only:
   `Auf dem iPhone landet die Datei in "Dateien". Von dort mit "Sichern" in die Fotos.` Honesty here is
   cheaper than a support ticket.
2. **Telegram** — the community already lives there. Two paths, and the cheap one ships first:
   *(a)* `Link teilen` opens `https://t.me/share/url?url=<public artifact URL>&text=<caption>` — zero
   backend, works today, the user picks the chat in their own client.
   *(b)* `Direkt senden` uploads the file with the Bot API `sendVideo`/`sendPhoto` (multipart) once the
   user has pasted a bot token and chat id into Ausgaben → Ziele. Stored as
   `cloudSettings.destinations[]`, token write-only in the API response.
3. **Discord** — a webhook URL pasted once. `POST` multipart with `payload_json` + the file. 10 MB free
   cap enforced by `maxBytes`. Rate limit 5 requests / 2 s, so exports queue.
4. **Öffentlicher Link** — `/a/:slug`, a `ShareLink` with `page:'artifact'`, `expiresAt` default **90
   Tage** (offered: 7 Tage / 90 Tage / unbegrenzt). The page renders the artifact, its data ribbon, and
   nothing else: no device id, no account, no other artifacts, no navigation into the app. `og:image` and
   `og:video` so it unfurls in Telegram, Discord, Signal and Matrix.
5. **Markdown / BBCode** — one button, two dialects, generated from the same sidecar with **hot-linked**
   image URLs pointing at `/a/:slug/file`, which XenForo and Discourse both render inline. This collapses
   "integrate with RollItUp, THCFarmer, ICMag, Percy's, autoflower.org" — five platforms with no usable
   API between them — into one copy button.

**The German advertising constraint is honoured by default.** No footer, no logo, no "Powered by" in any
generated text, on any card, in any og description. § 6 KCanG bans *Werbung und jede Form des Sponsorings*
for cannabis and Anbauvereinigungen with fines to €30,000, read broadly, and an auto-appended brand line on
thousands of German growers' posts is the single riskiest string available to us. Instead: Ausgaben →
`Absender im Bild` with three options, **default Aus** — `Aus` / `Nur Zeltname` / `Eigener Text`. A user
may type "Terp Control" into it themselves; we never write it for them. **Any branded default is blocked on
counsel and is not in v1.**

### 8.5 Image correlation, concretely

- `frameAt(t)`, `dataAt(t)`, one shared `timeCursor$`. Chart ↔ strip ↔ event list, three directions.
- **Every picture in the product carries a data ribbon.** The fullscreen viewer, the strip, the card, the
  event thumbnail, the export. The ribbon is the correlation made physical, and because it renders at
  export pixel ratio, what you see is what you send.
- **The film strip is an axis.** Thumbnails are positioned by timestamp on the chart's own x-scale, so
  uneven capture reads honestly as a gap. Delivery is **one sprite + a JSON index per window** (50 tiles
  under a day, 100 above, 256×160), not N image requests — one extra endpoint, and it makes the strip
  usable on a phone connection.
- **Culled frames are correlated too.** Tapping a gap shows `18 Bilder verworfen: 14 dunkel, 4 unscharf`
  with `Trotzdem zeigen`. That is a filter on one list, not a mode.
- **Search by picture:** the ribbon's values are indexable, so Das Buch offers `Bilder bei über 28 °C`.
  One query on `FrameMeta` joined to a coarse Influx roll-up. v1.1.

### 8.6 The camera alarm

A camera that stopped three days into flower must say so. `imageService.compressRtspStreams()` already
loops hourly over every device with an `rtspStream`; the check costs one query in that loop.

```
cloudSettings.cameraSilenceMinutes?: number   // default 180, 0 = off
```

On breach: one `DeviceLog { severity: 2, title: 'message-camera-silent',
data: { minutes } }`, which flows into the existing alarm/notification path, plus a persistent row on the
card: `Kamera seit 3 Std 20 Min. still  [ Testbild ]`. It resolves silently on the next frame. `cloudSettings`
is a cloud-side subdocument, so this needs **no firmware change** — verified against `shared-types`.

## 9. Clubs

**Attribution without authorisation.** `cloudSettings.actors: [{ actor_id, name, colour }]` — names the
owner types once in Einstellungen → `Wer ist am Zelt`. No accounts, no email, no `auth.middleware`
surgery. The picker appears on capture sheets only when more than one name exists. Every `Event` carries
`actorId` + a denormalised `actorName` (so renaming a person does not rewrite history).

This is deliberately a **label, not a gate**, and the UI says so once, in the setup copy:
`Namen sind eine Notiz, keine Anmeldung. Jeder mit Zugang zum Gerät kann jeden Namen wählen.`
Real memberships are §12's "later" — this delivers the club's actual daily need (who did what) in about
two days of work instead of blocking the whole family on an auth rewrite.

**The double feed.** At the moment the Gießen/Düngen sheet opens, query `Event` where
`type ∈ {water, feed}` ∧ `at > now − 6 h` ∧ (`plantIds` intersects the selection, or either side is `[]`).
If a hit exists:

```
⚠ Anna hat A1–A3 vor 1 Std 30 Min. gegossen (1,5 L).
```

The primary button relabels from `Speichern` to `Trotzdem speichern` — the same button, one deliberate
extra read. It is a **soft block**: never a dialog, never a second confirm step, never something you can
be locked out by. A double feed is the most expensive thing that happens in a shared room and this is the
whole intervention.

**Conditions.** `Condition` is the standing fact pinned to the tent door — not an event, not a task.
Created from the home card's `Notiz` sheet via a `Bleibt offen` toggle. Open conditions render in the
OFFEN block on the card for everyone, are included in every week artifact, and close with one tap
(`Erledigt — Chris, heute`). `CO2-Flasche fast leer`, `Steckdose 3 wackelt`, `A3 nicht gießen, übernässt`.

**Cumulative.** Das Buch → `Verbrauch`: per plant, per cycle, total litres and per-product ml, split by
actor, with a `Als CSV` exit and a rendered week sheet. This answers gap #3 directly.

**Privacy posture.** Device-scoped, thing-scoped, and privacy-maximal by default:

- `harvest.weightGrams` and plant counts are **never prompted**. They exist as optional fields behind
  `cloudSettings.recordWeights` (default off) and are excluded from every export unless a per-export
  toggle is turned on, with the copy naming exactly what is included.
- No artifact ever contains actor names, plant counts or weights unless the export sheet's
  `Namen und Mengen mitschicken` toggle is on. **Default off**, per export, never remembered as a setting.
- The public page carries no device id, no account, no location, no other artifacts.
- `Alles löschen` on the device removes artifacts, share links, frames and events for real — unlike
  today's `deleted` flag, which deletes nothing. Immutability is not a global posture; it would victimise
  an unregulated grower.
- We do not become the club's § 26 system of record. No per-member dispensing, ever.

## 11. Per-user-type walkthrough

**1 — Lazy monitoring only.** Opens the app once a fortnight. Sees the card: a picture-less data card,
`24,1 °C · 58 % · 87 % im Ziel`, `vor 40 Sek.` He never taps Details and never taps Teilen. Once a week a
Wochenbericht appears in Ausgaben without him asking, which is the whole product for him: the record got
kept while he did nothing. The one thing he does eventually tap is `⤓` on a week sheet, because he wants
to show someone that the tent is fine.

**2 — Same, with a camera.** The type the owner says is a top selling point, and the only one this concept
is fully built for. His card has a live still with the numbers on it. Every Sunday `Clip Woche N` renders
automatically (an option, on by default when a camera exists). He taps `⤓`, it lands in his gallery, he
posts it himself. Twelve weeks later `Clip ganzer Durchgang` — 4,000 culled and normalised frames,
resampled to a 30-minute beat, chaptered at the day he nudged the camera, under 14 MB, H.264, plays in
Telegram. That is the "hold in your hand" object.

**3 — Controls certain aspects (CO₂ or heating).** His card shows only the measures his kit reports and
only the outputs he owns — CO₂ absent entirely if there is no SCD4x, no dehumidifier tile if no
dehumidifier socket is paired. The ranked rows put CO₂ at the top when it deviates and drop it when it
does not. His week sheet shows time-in-band for exactly the two things he controls, which is the honest
answer to "did my kit do its job".

**4 — Full tent.** Gets the most out of `/film`: five panels, the output state-timeline lane showing which
socket ran when, the deviation fill, the annotation rail. He is also the one most likely to hit the
concept's honest limit — the five socket roles do not cover a humidifier or an exhaust fan, and this
concept does not pretend otherwise; it shows the roles that exist and names the absences.

**5 — Closed-loop DIY.** He never opens the card. He opens Depth 2 once, copies the sidecar JSON, sees it
is the same shape the artifact endpoint returns, and wires `/artifact/:id` plus the generic webhook
destination into his own system. The sidecar is his API in v1 — documented, versioned, and the same object
the UI reads, so it cannot silently drift. A real read/write API is v2 and this concept does not claim it.

**6 — Club.** Three people, one tent, one login. Names typed once. The Gießen sheet stamps who, the double
feed gets the amber line, the CO₂ bottle gets a Condition everyone sees, and `Verbrauch` reconstructs the
cycle in a table months later. The club's own need is served; the state's § 26 filing is refused, in
writing, in the settings copy.

**7 — Old device owner.** §10. He gets a card and a week sheet he never had, and his settings screen is
byte-identical to the one he knows.

**Capability lenses.** *Stoner:* one screen, one picture, three fat buttons, a tap counter with haptics,
nothing reorders under his thumb, and the destructive path always needs a second deliberate tap.
*Normal:* an object that looks like something he would post, which is the comparison he is actually making
against Instagram, not against AC Infinity. *Techie:* `⌄ Details` twice, and every number he sees is in
the file he downloads.

## 13. Honest weaknesses

**13.1 It is a camera-forward concept and the camera is a €30–60 upsell.** If most of the 150 first-series
buyers skip it, the headline is dark for them. The camera-less card is a real mitigation — everyone gets
an artifact — but it is a consolation, and a critic is right to say the concept's best hour is only
available to a subset of customers.

**13.2 Every export is an ffmpeg run.** The box already spends CPU on three rolling timelapses per camera
per hour. Adding user-triggered renders — a 12-week clip is minutes of encoding — needs a real queue, a
per-user rate limit and back-pressure UI. I have costed a naive job table and `pLimit`; at 150 devices
that is probably fine and at 1,500 it is definitely not, and I have not designed the scaling story.

**13.3 Mongo is not a video store.** Artifacts are `Buffer`s under the 16 MB BSON limit, so v1 clamps to
14 MB and the "whole grow" clip is therefore 720p or coarsely sampled. The thing the concept promises you
can hold is, in v1, slightly smaller than the promise. The fix is object storage and it is not in scope.

**13.4 Culling hides frames.** Nothing is deleted and the ledger is one tap away, but the default view
hides frames on heuristics with hand-picked thresholds. If the one frame that would have shown a grower
his spider mites is culled as `unscharf`, that is a real harm from a feature sold as a convenience. The
thresholds in §8.2 are first guesses and will need tuning against real tents, which we cannot do before
October because there are not yet real tents.

**13.5 `stoerung` is not person detection.** It is transient-change detection. A fan oscillating a leaf,
a door opening for four minutes, a passing shadow — the rule cannot tell them apart, and it will cull
some frames a grower wanted. Naming it *disturbance* rather than *person* is honesty, not a fix.

**13.6 The product optimises for an act many growers never perform.** A home screen designed as a share
preview is a strange home screen for someone who will never share anything. The counter-argument is that
the card is also the best possible single-glance status object and the ranked rows underneath carry the
rest — but it is an argument, not a proof, and it is the sharpest attack on this concept.

**13.7 § 6 KCanG could eat the exit paths late.** Every exit here sits next to a German advertising ban
with €30,000 fines and no case law on grow equipment. I have made the branded footer default-off and
blocked it on counsel, which handles the obvious risk. What I cannot rule out is counsel deciding the
neutral public page at our own domain is itself *Sponsoring* for an Anbauverein's post — which would kill
the `/a/:slug` path and, with it, the hot-linked Markdown generator that makes five forums reachable.
That is a late, expensive, external failure mode and it is not mitigable by design.

**13.8 Discovery of depth is the weak point of reveal-by-depth.** `⌄ Details` is always visible and always
worded, but a stoned user at 2am will not tap it, and a techie evaluating the app in ninety seconds may
conclude the numbers are not there. Ranked density and the sidecar-in-every-export soften it. It remains
the honest cost of refusing modes: nothing announces itself as "the advanced part", so nothing is found by
looking for the advanced part.

**13.9 H.264 costs storage.** Re-encoding every exported artifact out of HEVC is roughly 1.4–1.8× the
bytes for equal quality. It is the correct trade — an HEVC file that will not play in Firefox or Telegram
is not a shareable artifact at all — but it is a real cost paid in Mongo, on the box that is already the
bottleneck in 13.2.
